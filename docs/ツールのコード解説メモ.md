## 1. toQueryLiteral（値をクエリ用の文字列にする・内部）

**この関数の役割**
- クエリ文字列の中に値を埋め込めるように、値を `"..."`（ダブルクォート）で囲み、中に含まれる `\` と `"` を**エスケープ**（記号として扱わせるための印 `\` を前に付けること）します。
- 例: 値 `C-001` → `"C-001"`、値 `abc"d` → `"abc\"d"`
- `lookupValues`（2 節）で、検索条件を組み立てるときに使います。

```js
function toQueryLiteral(value) {
  const escaped = String(value).replace(/\\/g, '\\\\').replace(/"/g, '\\"');
  return `"${escaped}"`;
}
```

- `String(value)` … 数値（`123`）が渡されても、まず文字列（`'123'`）にそろえます。
- 置き換えを 2 回、**この順番で**行います。
  1. `.replace(/\\/g, '\\\\')` … `\` を 1 個見つけるたびに `\\`（2 個）にする。
  2. `.replace(/"/g, '\\"')` … `"` を見つけるたびに `\"` にする。
- 📝 読み替え: `/\\/g` と `'\\\\'` は、**書いてある `\` の数と、実際の `\` の数が違います**。
  - JavaScript では `\` 自体が「次の文字を特別扱いする」印なので、`\` を 1 個表すのに `\\` と 2 個書きます。
  - `/\\/g` = 「`\` 1 個」を探す正規表現（`g` = 全部の該当箇所）。
  - `'\\\\'` = 「`\` 2 個」の文字列。`'\\"'` = 「`\` 1 個と `"`」の 2 文字。
- 順番が大事な理由（ソースのコメントより）: もし先に `"` → `\"` をしてから `\` を 2 倍にすると、**さっき自分で足した `\` まで 2 倍**になってしまい、`abc"d` が `abc\\"d` という壊れた形になります。だから `\` を先に処理します。
- 最後に、テンプレート文字列 `` `"${escaped}"` `` で前後を `"` で囲んで返します。
- これをしないと、値に `"` が入っていたときにクエリの区切りが崩れ、kintone 側でエラーになったり、意図しない条件で検索されたりします。

## 2. lookupValues（マスタからルックアップ用の値を取ってくる）

**この関数の役割**
- マスタアプリで「`keyField` が `keyValue` に等しい」レコードを探し、`copies` で指定したフィールドの値を、**自分のアプリのフィールドコード**に付け替えて返します。
- 戻り値は `{ 自分のフィールドコード: { value: マスタの値 } }` の形なので、`addRecord` / `updateRecord` の `record` にそのまま混ぜられます。見つからなければ `null` です。
- 例（ソースの JSDoc より）:
  - `copies: { customer_name: 'customer_name', phone: 'customer_phone' }` で呼ぶと
  - → `{ customer_name: { value: '株式会社サンプル' }, customer_phone: { value: '03-0000-0000' } }`
- `copies` は `{ マスタのフィールドコード: 自分のアプリのフィールドコード }` という**対応表**です。左がマスタ側、右が自分側である点に注意してください。

### 塊 1: 引数を受け取り、コピーするフィールドが 1 つ以上あるか確かめる

```js
async function lookupValues(processName, masterApi, { keyField, keyValue, copies }) {
  const masterFields = Object.keys(copies);
  if (masterFields.length === 0) {
    throw new Error('KintoneRecordTools: copies にコピーするフィールドを 1 つ以上指定してください');
  }
```

- 📝 読み替え: `async function` = 「途中で通信の完了を**待つ**ことがある関数」。中で `await` が使え、呼び出した側は戻り値を `await lookupValues(...)` で受け取ります（戻り値は Promise = 「あとで結果が届く引換券」）。
- 📝 読み替え: 引数の `{ keyField, keyValue, copies }` = 「3 番目の引数として渡されたオブジェクトから、この 3 つのキーを**取り出して**同名の変数にする」（引数での分割代入）。
  - 例: `lookupValues('処理名', masterApi, { keyField: 'customer_code', keyValue: 'C-001', copies: {...} })` と呼ぶと、関数の中では `keyField = 'customer_code'` などとして使えます。
  - 3 番目の引数そのものを省略すると、取り出し元が無いのでエラーになります。
- `Object.keys(copies)` … 対応表の**左側（キー）だけ**を配列にします。つまりマスタ側のフィールドコードの一覧です。
  - 例: `{ customer_name: 'customer_name', phone: 'customer_phone' }` → `['customer_name', 'phone']`
- 一覧が空（`copies` が `{}`）なら、何もコピーできないので、通信する前にエラーにします。なお、このメッセージには処理名は入っていません（塊 4 や 3 節のエラーには `[処理名]` が入ります）。

### 塊 2: マスタアプリを検索する

```js
  const records = await masterApi.getRecords(processName, {
    query: `${keyField} = ${toQueryLiteral(keyValue)}`,
    fields: masterFields,
  });
```

- 実際の通信は、渡された `masterApi`（マスタアプリ用の `KintoneRecordApi`）の `getRecords` に任せます。処理名もそのまま渡すので、通信でエラーが起きたときは、共通部品の `KintoneRecordApiError` に処理名が入ります。
- `await` … 検索結果（レコードの配列）が届くまで、ここで待ちます。
- `query` … 検索条件。テンプレート文字列で組み立てています。
  - 例: `keyField = 'customer_code'`、`keyValue = 'C-001'` なら `customer_code = "C-001"`。
  - 値の側だけを `toQueryLiteral`（1 節）で囲んでエスケープしています。`keyField` はフィールドコードなので囲みません。
- `fields` … 取ってくるフィールドを、コピーに必要なもの（塊 1 の `masterFields`）だけに絞ります。通信量を減らすためです。
- `keyField` は `fields` に入れていませんが、検索条件に使うだけなら取得する必要はありません。

### 塊 3: 見つからなければ null を返す

```js
  const masterRecord = records[0];
  if (!masterRecord) {
    return null;
  }
```

- 結果の配列の**先頭の 1 件**だけを使います。
  - `keyField` はマスタ側で値が重複しない（「値の重複を禁止する」設定の）フィールドである前提です（ソースの JSDoc より）。
  - もし複数見つかっても、エラーにはせず先頭の 1 件（kintone の既定の並び順で最初のもの）を使います。
- 0 件のとき、`records[0]` は `undefined`（何も無い）になり、`!masterRecord` が `true` になるので `null` を返します。
  - 「見つからない」はエラーではなく**普通にありうる結果**として扱っています。呼び出し側は `if (copied) { ... }` で分けられます。

### 塊 4: 値を自分のアプリのフィールドコードに付け替える

```js
  const copiedValues = {};
  for (const [masterField, ownField] of Object.entries(copies)) {
    if (!(masterField in masterRecord)) {
      // フィールドコードの書き間違いを、値が空のまま気づかず登録してしまうのを防ぐ
      throw new Error(`KintoneRecordTools: [${processName}] マスタのレコードにフィールド ${masterField} がありません`);
    }
    copiedValues[ownField] = { value: masterRecord[masterField].value };
  }
  return copiedValues;
}
```

- `copiedValues` … 結果を入れる空の入れ物。
- `for (const [masterField, ownField] of Object.entries(copies))` … 対応表を「マスタ側・自分側」の 1 組ずつ取り出して繰り返します。
  - 例: 1 周目は `masterField = 'customer_name'`、`ownField = 'customer_name'`、2 周目は `masterField = 'phone'`、`ownField = 'customer_phone'`。
- 📝 読み替え: `!(masterField in masterRecord)` = 「`masterRecord` に `masterField` という**キーが無い**」。
  - `in` は「キーがあるか」を調べる演算子です。値が空（`''`）でも、キーさえあれば `true` です。
  - `!` を `( )` の外に付けているのは、`!masterField in masterRecord` と書くと先に `!masterField` が計算されてしまい、意味が変わるためです。
- キーが無いときはエラーにします。
  - フィールドコードを書き間違えると、取得したレコードにそのキーが含まれません。黙って空の値を返すと、空のまま登録されて気づけないので、ここで止めます（ソースのコメントの意図）。
  - メッセージには `[処理名]` と、見つからなかったフィールドコードが入ります。
- キーがあれば、マスタの値 `masterRecord[masterField].value` を取り出し、**自分側のフィールドコード** `ownField` をキーにして `{ value: ... }` で包み直して入れます。
  - 取得したときに付いていた `type` は付けません。登録・更新用の形は `{ value }` だけで足りるからです。
- 全部入れ終わったら、入れ物を返します。これがそのまま `record` に混ぜられる形です。
  - 例（ソースの JSDoc より）: `record: { ...copied, customer_code: { value: 'C-001' } }`

## 3. nextNumber（次の番号を決める）

**この関数の役割**
- 「`prefix` + ゼロ埋めの連番」で、次の番号を返します。例: 既存が `P-0001` 〜 `P-0007` なら `'P-0008'`。該当する既存値がなければ `'P-0001'`。
- やり方は「対象フィールドの既存値を**全件**取り出し、`prefix` で始まる値の**末尾の数字**の最大値 + 1」です。
- 注意点（ソースの JSDoc より）
  - 番号を決めてから保存するまでの間に、他の人も同じ番号を決めると**番号が重なる**ことがあります。対象フィールドには「値の重複を禁止する」設定を併用し、重なったときは保存エラーで気づけるようにします。
  - 全件取得に `getRecords` を使うため、対象アプリのレコードが 10,500 件を超えるとエラーになります。

### 塊 1: 対象フィールドの値を全件取ってくる

```js
async function nextNumber(processName, api, { field, prefix, digits }) {
  const records = await api.getRecords(processName, { fields: [field] });
```

- 引数の形は `lookupValues` と同じで、3 番目のオブジェクトから `field`（番号を入れるフィールド）・`prefix`（前に付ける文字列）・`digits`（ゼロ埋めの桁数）を取り出します。
- `getRecords` に `query` を渡していないので、**全レコード**が対象です。
- `fields: [field]` で、取ってくるのは番号のフィールド 1 つだけに絞っています。全件取るので、通信量を減らす効果が大きい部分です。

### 塊 2: 1 件ずつ見て、使えない値は飛ばす

```js
  let maxNumber = 0;
  for (const record of records) {
    if (!(field in record)) {
      // フィールドコードの書き間違いで「該当なし → 0001」を返してしまうのを防ぐ
      throw new Error(`KintoneRecordTools: [${processName}] レコードにフィールド ${field} がありません`);
    }
    const value = String(record[field].value || '');
    if (!value.startsWith(prefix)) {
      continue;
    }
```

- `maxNumber` … 今まで見つけた番号の最大値。最初は `0` です。後で書き換えるので `const` ではなく `let` にしています。
- `for (const record of records)` … レコードを 1 件ずつ取り出して繰り返します。
- フィールドの有無のチェックは、2 節の塊 4 と同じ考え方です。
  - 書き間違いのまま進むと、どのレコードからも番号が見つからず「`P-0001`」を返してしまい、既存の番号と重なります。それを防ぐために止めます。
  - このチェックは繰り返しの**中**にあるので、レコードが 0 件のときは働きません（そのときは繰り返しが 1 回も回らず、`prefix` + `1` のゼロ埋めが返ります）。
- `String(record[field].value || '')`
  - `A || ''` は「`A` が空っぽ（`''`・`null`・`undefined` など）なら `''` を使う」既定値の書き方です。
  - 最後に `String(...)` で必ず文字列にそろえます。
- 📝 読み替え: `value.startsWith(prefix)` = 「`value` が `prefix` で**始まる**か」。始まらなければ `continue` で、この 1 件を飛ばして次のレコードへ進みます。
  - 例: `prefix = 'P-'` のとき、`'Q-0003'` や空の値は飛ばされます。

### 塊 3: 末尾の数字を取り出し、最大値を更新する

```js
    const tailDigits = /(\d+)$/.exec(value.slice(prefix.length));
    if (tailDigits) {
      maxNumber = Math.max(maxNumber, Number(tailDigits[1]));
    }
  }
```

- `value.slice(prefix.length)` … 先頭の `prefix` の文字数ぶんを切り落とした残りです。例: `'P-0007'` → `'0007'`。
- 📝 読み替え: `/(\d+)$/` = 「**末尾**に続く数字（1 個以上）」を探す正規表現。
  - `\d+` … 数字が 1 個以上。`$` … 文字列の最後。`( )` … その部分を後で取り出せるように印を付ける。
  - `.exec(...)` は、見つかれば結果の配列（`[1]` に印を付けた部分）、見つからなければ `null` を返します。
  - 例: `'0007'` → `tailDigits[1]` は `'0007'`。`'12A'` → 末尾が数字でないので `null`（この値は無視）。
  - **末尾の数字だけ**を見るので、`'P-A12'` のように途中に文字があっても、末尾が数字なら `12` として数えます。
- `Number('0007')` → `7`。先頭の 0 は消えて、ただの数値になります。
- `Math.max(今の最大値, この値)` … 大きい方を残します。全件見終わると、`maxNumber` が既存の番号の最大値になっています。
- 数字が見つからなかった値（`tailDigits` が `null`）は、何もせず次へ進みます。

### 塊 4: 最大値 + 1 をゼロ埋めして、prefix を付ける

```js
  return prefix + String(maxNumber + 1).padStart(digits, '0');
}
```

- `maxNumber + 1` が次の番号です。例: `7 + 1` → `8`。
- `String(...).padStart(digits, '0')` … 文字列にしてから、`digits` 桁になるまで左側を `'0'` で埋めます。例: `digits = 4` なら `'8'` → `'0008'`。
- 桁が足りているときは何もしないので、**桁を超えても切り捨てません**。例: `P-9999` の次は `'P-10000'`（ソースの JSDoc より）。
- 最後に `prefix` を前に付けて返します。例: `'P-' + '0008'` → `'P-0008'`。

## 4. 型定義（JSDoc に書かれた型）

**この節の役割**
- このファイルには、`type` 宣言のような独立した型定義はありません。型は各関数の直前の **JSDoc**（`/** ... */` のコメント）に `@param` / `@returns` として書かれています。
- 動きには関係しませんが、エディタ（VS Code など）がこれを読み取って、呼び出し時に引数の候補や型の誤りを教えてくれます。

### 4-1. toQueryLiteral の型

```js
 * @param {string | number} value 埋め込む値
 * @returns {string} 例: 値 abc"d → "abc\"d"
```

- 📝 読み替え: `{string | number}` = 「文字列**または**数値」。`|` は「どちらか」の意味です。
- 戻り値は必ず文字列です。

### 4-2. lookupValues の型

```js
 * @param {string} processName 処理名（エラー時にどの処理で失敗したかを示す）
 * @param {KintoneRecordApi} masterApi マスタアプリ用の KintoneRecordApi
 * @param {object} options
 * @param {string} options.keyField マスタ側のキーフィールドのフィールドコード
 * @param {string | number} options.keyValue 探す値
 * @param {Record<string, string>} options.copies { マスタのフィールドコード: 自分のアプリのフィールドコード } の対応表
 * @returns {Promise<Record<string, { value: unknown }> | null>} 自分のアプリ用の値。見つからなければ null
```

- `{KintoneRecordApi}` … 共通部品のクラス名がそのまま型として使われています。「`new KintoneRecordApi(...)` で作ったもの」という意味です。
- `@param {object} options` と `options.keyField` … 3 番目の引数（コードでは分割代入しているので名前が無い）を、型の上では `options` と名付け、その中身のキーを 1 つずつ説明する書き方です。
- 📝 読み替え: `Record<string, string>` = 「キーも値も文字列のオブジェクト」。`{ customer_name: 'customer_name', ... }` のような対応表を表します。
- 📝 読み替え: `Promise<X | null>` = 「あとで `X` か `null` が届く引換券」。`async` 関数の戻り値なので `Promise<...>` で包まれ、`await` すると中身（`X` か `null`）が取り出せます。
  - ここでの `X` は `Record<string, { value: unknown }>` = 「キーが文字列で、値が `{ value: 何か }` のオブジェクト」。
  - `unknown` = 「何の型か決まっていない」。マスタのフィールドの種類によって、値は文字列だったり配列だったりするためです。

### 4-3. nextNumber の型

```js
 * @param {string} processName 処理名（エラー時にどの処理で失敗したかを示す）
 * @param {KintoneRecordApi} api 採番するアプリ用の KintoneRecordApi
 * @param {object} options
 * @param {string} options.field 番号を入れるフィールドのフィールドコード
 * @param {string} options.prefix 番号の前に付ける文字列（例: 'P-'）
 * @param {number} options.digits ゼロ埋めの桁数（例: 4 → 0008）
 * @returns {Promise<string>} 次の番号（例: 'P-0008'）
```

- 書き方は 4-2 と同じです。`digits` だけが `number`（数値）です。
- 戻り値は `Promise<string>` で、`await` すると `'P-0008'` のような文字列が取り出せます。

## 5. グローバルに公開（ファイルの最後）

**この節の役割**
- 箱（IIFE）の中で作った関数のうち、**利用者に使ってほしい 2 つだけ**を 1 つのオブジェクトにまとめて外に出します。

```js
globalThis.KintoneRecordTools = Object.freeze({
  lookupValues,
  nextNumber,
});
```

- 📝 読み替え: `globalThis` = 「どこからでも見える共有の場所」。ここに置いたものは、後から読み込む JS からそのまま `KintoneRecordTools.nextNumber(...)` のように使えます。
- `{ lookupValues, nextNumber }` は `{ lookupValues: lookupValues, nextNumber: nextNumber }` の省略形です。
- 📝 読み替え: `Object.freeze(...)` = 「凍らせる」。後から `KintoneRecordTools.nextNumber = ...` のように中身を書き換えられないようにします。
- 公開されないもの: `toQueryLiteral`（内部の道具なので）。
- このため、kintone のカスタマイズ設定では、このファイルを利用側の JS より**先に**（そして `kintoneRecordApi.js` より後に）読み込みます。

実務でつまずきやすいものだけに絞っています。

| `async function` / `await` | 通信の完了を待つ関数。戻り値は Promise で、`await` で中身を受け取る | 2 節 |
| `function f(a, { x, y })` | 引数での分割代入。渡されたオブジェクトから `x`・`y` を取り出す | 2 節 |
| `!(key in obj)` | `obj` に `key` というキーが無い（`!` は `( )` の外に付ける） | 2 節 |
| `.startsWith(prefix)` | 文字列が `prefix` で始まるか | 3 節 |
| `/(\d+)$/` / `.exec(文字列)` | 末尾に続く数字を探す正規表現。見つかれば `[1]` に数字部分、無ければ `null` | 3 節 |
| `{string \| number}` | JSDoc の型。文字列または数値 | 4 節 |
| `Record<string, string>` | JSDoc の型。キーも値も文字列のオブジェクト | 4 節 |
