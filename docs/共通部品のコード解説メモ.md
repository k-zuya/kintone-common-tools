## 1. KINTONE_LIMITS（件数制限の定数）

**このメソッドの役割**（※メソッドではなく定数です）
- kintone の「1 回に扱える件数の上限」を 1 か所にまとめた**数字の一覧表**です。

### 塊 1: 一覧表を作って凍らせる

```js
const KINTONE_LIMITS = Object.freeze({
  /** 登録・更新・削除（複数）の 1 回あたりの上限件数 */
  WRITE_RECORDS: 100,
  /** 取得（複数・カーソル）の 1 回あたりの上限件数 */
  GET_RECORDS: 500,
```

```js
  /** バルクリクエストの 1 回あたりの上限リクエスト数 */
  BULK_REQUESTS: 20,
  /** 取得（複数）で指定できる offset の上限 */
  MAX_OFFSET: 10000,
});
```

- 4 つの数字に名前を付けています。
  - `WRITE_RECORDS: 100` … 登録・更新・削除は 1 回 100 件まで
  - `GET_RECORDS: 500` … 取得は 1 回 500 件まで
  - `BULK_REQUESTS: 20` … バルク（複数の API をまとめて送る仕組み。14 節）は 1 回 20 リクエストまで
  - `MAX_OFFSET: 10000` … offset（複数取得で「何件目から取るか」の指定）は 10,000 まで
- 📝 読み替え: `Object.freeze(...)` = 「凍らせる」。プロパティを後から書き換えられないようにします。`const` だけでは「変数の付け替え」を防ぐだけで、中身の書き換えは防げないため併用しています。
- 数字を直接あちこちに書かず、ここに名前付きで集めることで「100 って何の数？」と迷わずにすみます。

## 3. 内部の補助処理（クラスの外の小さな関数）

**この節の役割**
- 本体のメソッドが共通して使う「下ごしらえ係」5 つです。利用者が直接呼ぶものではありません（箱の中にあるので外から見えません）。

### 3-1. splitIntoChunks（配列を N 件ずつに分ける）

**役割**: 長いリストを「100 件ずつ」「20 件ずつ」のように**小分けの束**にします。

```js
function splitIntoChunks(items, size) {
  const chunks = [];
  for (let start = 0; start < items.length; start += size) {
    chunks.push(items.slice(start, start + size));
  }
  return chunks;
}
```

- `start` を 0 から `size` ずつ増やしながら、配列の終わりまで繰り返します。
- `items.slice(start, start + size)` … `start` 番目から `size` 個を切り出す。
- `chunks.push(...)` … 切り出した束を `chunks` の末尾に追加。
- 例: 250 件を 100 件ずつ → `[100件, 100件, 50件]` の 3 束。

### 3-2. extractKintoneErrorInfo（エラーからコードとメッセージを取り出す）

**役割**: kintone から返ってきたエラーの中から「エラーコード」と「メッセージ」を探し出します。エラーの形が場合によって違うので、3 段構えで探します。

#### 塊 1: ふつうの形なら、そのまま取り出す

```js
if (error && error.code) {
  return { code: String(error.code), message: String(error.message || '') };
}
```

- 「`error` があって、しかも `error.code` もあるなら」そのまま返します。
- 📝 読み替え: `error && error.code` = **ガード**。`error` が `null` / `undefined` なら右側を評価しないので、「無いもののプロパティを読んで TypeError」を防げます。
- 📝 読み替え: `A || ''` = 「A が falsy（`undefined`・空文字など）なら `''`」。初期値の代わりによく使う書き方です。

#### 塊 2: バルクの失敗なら、results の中から探す

```js
const failedResult =
  error && Array.isArray(error.results)
    ? error.results.find((result) => result && result.code)
    : undefined;
if (failedResult) {
  return { code: String(failedResult.code), message: String(failedResult.message || '') };
}
```

- バルクリクエストが失敗したときは、エラーコードが一番外ではなく `results`（各リクエストの結果リスト）の中に入っています。そこを探します。
- 「`results` が配列なら、`code` を持つ最初の要素を `.find` で探す。配列でなければ `undefined`」という三項演算子です。

#### 塊 3: どちらでもなければ UNKNOWN

```js
const fallbackMessage = error && error.message ? String(error.message) : String(error);
return { code: 'UNKNOWN', message: fallbackMessage };
```

- コードが見つからなかったときの最後の手。コードは `'UNKNOWN'`（不明）にします。
- メッセージは「`error.message` があればそれ、なければエラーそのものを文字にしたもの」。

### 3-3. toQueryLiteral（クエリに埋め込む値を安全な形にする）

**役割**: 値を `"..."` で囲み、中の `"` や `\` を**エスケープ**（記号としてではなく文字として扱わせる印を付けること）します。upsert の検索で使います。

```js
function toQueryLiteral(value) {
  const escaped = String(value).replace(/\\/g, '\\\\').replace(/"/g, '\\"');
  return `"${escaped}"`;
}
```

- `.replace(/\\/g, '\\\\')` … 値の中の `\` を `\\` に置き換え（`/.../g` は「全部の該当箇所」を表す検索パターン）。
- `.replace(/"/g, '\\"')` … 値の中の `"` を `\"` に置き換え。
- `\` を先に処理するのは、後から付けた `\` まで二重に置き換えないため。
- 最後に前後を `"` で囲んで返します。
- 例: 値 `abc"d` → `"abc\"d"`。値に `"` が入っていてもクエリが壊れません。

### 3-4. toRecordRefParams（更新先の指定を API 用の形に直す）

**役割**: 「ID 指定」か「updateKey 指定」かを見分けて、kintone に渡す形にします。

```js
function toRecordRefParams(ref) {
  if ('id' in ref) {
    return { id: ref.id };
  }
  return { updateKey: { field: ref.updateKey.field, value: ref.updateKey.value } };
}
```

- 📝 読み替え: `'id' in ref` = 「`ref` に `id` というプロパティがあるか？」。値が `undefined` かどうかではなく、**キーの有無**で判定します。
- あれば `{ id: ... }` だけを返す。なければ `{ updateKey: { field, value } }` を返す。
- 必要な項目だけを取り出して作り直すので、余計なものが API に混ざりません。

### 3-5. toUpdateParams（更新 1 件分を API 用の形に直す）

**役割**: 更新先（3-4 の結果）＋更新内容 `record` ＋（あれば）`revision` を 1 つにまとめます。

```js
function toUpdateParams(target) {
  const params = { ...toRecordRefParams(target), record: target.record };
  if (target.revision !== undefined) {
    params.revision = target.revision;
  }
  return params;
}
```

- 📝 読み替え: `{ ...X, record: ... }` = **スプレッド構文**。X のプロパティを展開してコピーし、さらに `record` を足した新しいオブジェクトを作ります（浅いコピー）。
  - 例: X が `{ id: 10 }` なら → `{ id: 10, record: {...} }`
- `revision`（リビジョン = レコードの版番号）は、渡されたときだけ付けます。付けると「その版のときだけ更新する」安全装置になります（楽観ロック = 他の人が先に直していたら失敗させる仕組み）。

## 5. getRecord（1 件取得）

**このメソッドの役割**
- レコード ID を指定して、レコードを 1 件取ってきます。

### 塊 1: kintone に頼んで、レコードを返す

```js
async getRecord(processName, id) {
  const response = await this._call(processName, 'GET', '/k/v1/record.json', {
    app: this.appId,
    id: id,
  });
  return response.record;
}
```

- `this._call(...)` は kintone に頼む**窓口係**です（中身は 16 節）。ここでは「処理名・やり方（GET = 取得）・API の住所・渡す材料」を渡せば kintone に頼んでくれる、と思っておけば十分です。
- 渡す材料は `app`（アプリ ID）と `id`（レコード ID）。
- 返ってきた答え `response` の中の `record` だけを取り出して返します。
- 全メソッド（`req` を除く）は `async` なので、使う側も `const record = await api.getRecord(...)` のように `await` を付けて呼びます。

## 6. getRecords（条件に合うものを全部取得）

**このメソッドの役割**
- 条件に合うレコードを**全部**取ってきます。kintone は 1 回 500 件までしか返さないので、500 件ずつ自動で何往復もします。
- ただし offset の上限のため、取れるのは **10,500 件まで**。それを超えそうなら、API を呼ぶ前にエラーで止め、カーソル版（`getRecordsByCursor`）へ案内します。

### たとえ: 500 件ずつ運ぶ台車

- 倉庫（kintone）からレコードを運び出すとき、**台車には 1 回 500 件までしか載りません**。
- そこで「何件目から積むか」を書いたメモ（**offset**）を渡して、台車を何往復もさせます。
  - 1 便目: offset 0 → 1〜500 件目
  - 2 便目: offset 500 → 501〜1,000 件目
  - …
- **台車が満杯でなく戻ってきたら**「もう倉庫に残りはない」＝最後の便なので終わりです。
- **満杯で戻ってきたら**、まだ残っているかもしれないので、メモを 500 進めてもう一往復します。

### 塊 1: 準備（条件と 1 回の件数）

```js
async getRecords(processName, options = {}) {
  const baseQuery = options.query || '';
  const limit = KINTONE_LIMITS.GET_RECORDS;
```

- 📝 読み替え: `options = {}` = デフォルト引数。渡されなかったら `{}` を使うので、`options.query` を読んでもエラーになりません。だから `api.getRecords('処理名')` だけでも動きます。
- `baseQuery` … 利用者が指定した絞り込み条件。指定が**なければ** `''`（空 = 全部）。
- `limit` … 台車の積載量 = 500。

### 塊 2: 集める箱と、メモの初期位置

```js
const allRecords = [];
let offset = 0;
```

- `allRecords` … 運んできたレコードをためておく空の箱。
- `offset` … 「何件目から積むか」のメモ。最初は 0（先頭から）。後で増やすので `let` です。

### 塊 3: 1 便ぶんの注文書を書く

```js
while (true) {
  const params = {
    app: this.appId,
    query: `${baseQuery} limit ${limit} offset ${offset}`.trim(),
  };
  if (options.fields) {
    params.fields = options.fields;
  }
```

- `while (true)` なので、ループを抜けるのは中の `return`（取り終わり）か `throw`（エラー）だけです。
- `query` に、利用者の条件の後ろへ `limit 500 offset 〇〇` を**付け足して**います。
  - 例: 条件 `status in ("未着手")`、1 便目 → `status in ("未着手") limit 500 offset 0`
  - 条件なしだと先頭が空白になる（` limit 500 offset 0`）ので、`.trim()`（前後の空白を取る）で整えます。
  - だから利用者は、自分の `query` に `limit` / `offset` を書いてはいけません（二重になるため）。
- `fields`（取るフィールドの指定）は、指定されたときだけ付けます。

### 塊 4: 台車を出して、荷物を箱へ

```js
const response = await this._call(processName, 'GET', '/k/v1/records.json', params);
allRecords.push(...response.records);
```

- 窓口係 `_call` に注文書を渡して、1 便ぶん取ってきます。
- 📝 読み替え: `push(...配列)` = 配列の要素を**ばらして**全部追加する（ここでの `...` もスプレッド）。`...` を付けないと「配列ごと 1 要素」として入ってしまい、配列の配列になります。

### 塊 5: 最後の便か判定、そうでなければメモを進める

```js
if (response.records.length < limit) {
  return allRecords;
}
offset += limit;
```

- `response.records.length` = 今回運んできた件数。
- 500 件**未満**なら台車は満杯でなかった＝最後の便。集めた全部を返して終わり。
- 満杯（500 件）なら、メモを 500 進めて次の便へ。

### 塊 6: offset の上限を超える前に止める（検知）

```js
if (offset > KINTONE_LIMITS.MAX_OFFSET) {
  throw new Error(
    `KintoneRecordApi: [${processName}] offset の上限（${KINTONE_LIMITS.MAX_OFFSET.toLocaleString('en-US')}）を超えるため、getRecords では取得できません。` +
      `10,000 件を超える全件取得には getRecordsByCursor を使ってください`
  );
}
```

- kintone では **offset を 10,000 までしか指定できません**。
- そのまま 10,000 を超える offset で頼むと、kintone から分かりにくいエラーが返ってきます。
- そこで、**次の便を出す前に**メモ（offset）を確認し、10,000 を超えていたら**API を呼ばずに**エラーを投げます。
- メッセージで「`getRecordsByCursor` を使ってください」と**次の手を案内**します。
- `toLocaleString('en-US')` = 数字を `10,000` のようにカンマ区切りで表示する。
#### 具体的に何便目で止まるか

| 便 | offset | 運ぶ範囲 |
|---|---|---|
| 1 便目 | 0 | 1〜500 件目 |
| … | … | … |
| 20 便目 | 9,500 | 9,501〜10,000 件目 |
| 21 便目 | 10,000 | 10,001〜10,500 件目（offset 10,000 は「ちょうど上限」なので OK） |
| 22 便目 | 10,500 | **出発前に検知してエラー**（10,500 > 10,000） |

- つまり取れるのは **10,500 件まで**。
- **注意点**:
  - 該当がちょうど 10,500 件のときもエラーになります。21 便目が満杯（500 件）で戻ると「まだあるかも」と判断し、22 便目の出発前に止まるためです。
  - ここで投げるのは `KintoneRecordApiError` ではなく、**ふつうの `Error`** です（kintone の失敗ではなく、部品側の事前チェックだから）。

## 7. getRecordsByCursor（カーソルで全部取得・10,000 件超え用）

**このメソッドの役割**
- 10,000 件を超えるような大量のレコードを、**カーソル**（kintone 側に置く「しおり」。どこまで読んだかを覚えてくれる）を使って全部取ってきます。
- しおりの作成 → 読み進め → （失敗時の）片付けまで、このメソッドの中で完結します。

### 塊 1: しおりを作る注文書

```js
async getRecordsByCursor(processName, options = {}) {
  const createParams = {
    app: this.appId,
    size: KINTONE_LIMITS.GET_RECORDS,
  };
```

- `size` = 1 回に読む件数（500）。
- こちらは offset を使わないので、10,000 の壁がありません。

### 塊 2: 条件とフィールドは、指定されたときだけ付ける

```js
if (options.query) {
  createParams.query = options.query;
}
if (options.fields) {
  createParams.fields = options.fields;
}
```

- `getRecords` と違い、query に `limit` / `offset` を付け足すことはしません。

### 塊 3: しおりを作ってもらう

```js
const cursor = await this._call(processName, 'POST', '/k/v1/records/cursor.json', createParams);
```

- `POST`（作成）でカーソルを作ります。返ってきた `cursor.id` が、しおりの番号です。

### 塊 4: しおりを使って最後まで読む

```js
try {
  const allRecords = [];
  let hasNext = true;
  while (hasNext) {
    const response = await this._call(processName, 'GET', '/k/v1/records/cursor.json', {
      id: cursor.id,
    });
```

```js
    allRecords.push(...response.records);
    hasNext = response.next;
  }
  return allRecords;
```

- `while (hasNext)` = 「続きがある間、繰り返す」。
- 毎回しおり番号だけを渡して `GET`（取得）すると、kintone が続きの 500 件を返してくれます。
- `response.next` が `true` なら続きあり、`false` なら読み切り。読み切ったら全部を返します。
- 最後まで読み切ると、kintone 側でしおりは**自動で削除**されます。

### 塊 5: 途中で失敗したら、しおりを片付けてからエラーを伝える

```js
} catch (error) {
  await this._deleteCursorQuietly(cursor.id);
  throw error;
}
```

- 途中で失敗すると、しおりが kintone 側に残ってしまいます。そこで `_deleteCursorQuietly`（16 節）で片付けます。
- 片付けたあと、元のエラーを `throw error;` で**そのまま投げ直し**ます。呼んだ側には本当の失敗理由が届きます。
- 補足: しおりの**作成自体**（塊 3）が失敗した場合は、`try` に入る前なので片付けは動きません（片付けるしおりがまだ無いため）。

## 10. updateRecord（1 件更新）

**このメソッドの役割**
- レコードを 1 件更新し、更新後のリビジョンを返します。更新先は「ID」か「updateKey（重複禁止フィールドの値）」のどちらかで指定します。

### 塊 1: 更新して、新しい版番号を返す

```js
async updateRecord(processName, target) {
  const response = await this._call(processName, 'PUT', '/k/v1/record.json', {
    app: this.appId,
    ...toUpdateParams(target),
  });

}
```

- `PUT`（更新）で頼みます。

- 答えから `revision`（更新後の版番号）だけを返します。
- 使い方の例（ソースのコメントより）:
  - ID 指定: `api.updateRecord('金額修正', { id: 10, record: { amount: { value: 5000 } } })`

## 12. upsert（あれば更新、なければ登録）

**このメソッドの役割**
- キーフィールド（値の重複が禁止されたフィールド）の値でレコードを探し、**あれば更新、なければ登録**します。
- 結果の `action` で、どちらをしたか（`'updated'` / `'added'`）が分かります。

### 塊 1: キーを取り出して、1 件だけ探す

```js
async upsert(processName, target) {
  const { field, value } = target.updateKey;
  const searchResponse = await this._call(processName, 'GET', '/k/v1/records.json', {
    app: this.appId,
    query: `${field} = ${toQueryLiteral(value)} limit 1`,
    fields: ['$id'],
  });
```

- `const { field, value } = target.updateKey;` … **分割代入**（2 節で初登場）のふつうの形。`target.updateKey` の中の `field` と `value` を、それぞれ同じ名前で取り出します。
- 検索の条件は例えば `project_code = "P-0001" limit 1`。値は `toQueryLiteral`（3-3）で安全な形にしてから埋め込みます。
- `limit 1` … 1 件見つかれば十分。
- `fields: ['$id']` … レコード ID だけ取ればよいので、他のフィールドは取りません（軽くするため）。

### 塊 2: 見つかったら更新

```js
const existingRecord = searchResponse.records[0];
if (existingRecord) {
  const { revision } = await this.updateRecord(processName, target);
  return { action: 'updated', id: String(existingRecord.$id.value), revision: revision };
}
```

- `records[0]` = 検索結果の**最初の 1 件**。0 件なら `undefined`。
- 見つかったら `updateRecord`（10 節）で更新します。`target` には `updateKey` が入っているので、updateKey 指定の更新になります。
- `{ revision }` で、更新結果から版番号だけを取り出しています。
- ID は、検索で取った `$id` の値を文字列にして返します（登録時と形をそろえるため）。

### 塊 3: 見つからなければ、キーの値を足して登録

```js
const recordWithKey = { ...target.record, [field]: { value: value } };
const { id, revision } = await this.addRecord(processName, recordWithKey);
return { action: 'added', id: id, revision: revision };
```

- 登録する中身に、**キーフィールドの値を自動で足して**います（利用者が `record` に書き忘れても大丈夫なように）。
- 📝 読み替え: `[field]: ...` = 「`field` という**名前そのもの**ではなく、`field` に入っている値（例: `project_code`）を項目名にする」。
- `addRecord`（8 節）で登録し、ID と版番号を返します。
- 補足:
  - `revision` は**更新のときだけ**使われます。登録のときは使われません。
  - 「探す」と「登録する」は別々の 2 回の通信です。その間に他の人が同じキーで登録した場合は、重複禁止の設定により登録側がエラーになります（だからキーフィールドは重複禁止である必要があります）。

## 13. deleteRecords（複数削除・100 件ずつ自動分割）

**このメソッドの役割**
- レコード ID のリストを渡して、まとめて削除します。100 件ずつ自動で分けます。リビジョンのリストも任意で渡せます。
- 注意: 途中で失敗すると、それより前の束は**削除済み**になります。

### 塊 1: ID と版番号を、それぞれ 100 件ずつの束にする

```js
async deleteRecords(processName, ids, revisions) {
  const idChunks = splitIntoChunks(ids, KINTONE_LIMITS.WRITE_RECORDS);
  const revisionChunks = revisions
    ? splitIntoChunks(revisions, KINTONE_LIMITS.WRITE_RECORDS)
    : [];
```

- ID を 100 件ずつの束に。
- 版番号は、**渡されていれば**同じく 100 件ずつに、渡されていなければ空のリスト（三項演算子）。
- ID と版番号は**同じ順番**で渡す約束なので、束の 1 番目どうし、2 番目どうしが対応します。

### 塊 2: 1 束ずつ削除

```js
for (let i = 0; i < idChunks.length; i++) {
  const params = { app: this.appId, ids: idChunks[i] };
  if (revisions) {
    params.revisions = revisionChunks[i];
  }
  await this._call(processName, 'DELETE', '/k/v1/records.json', params);
}
```

- `for...of` ではなく番号 `i` で回しているのは、ID の束と版番号の束を同じ番号で対応させるためです。
- `i` 番目の ID の束と、`i` 番目の版番号の束（あれば）を組にして `DELETE`（削除）します。
- 戻り値はありません（削除は「消えた」ことが結果なので）。

## 16. 内部メソッド（_call / _deleteCursorQuietly）

**この節の役割**
- 名前が `_`（アンダースコア）で始まるのは「**内部用**。利用者は直接呼ばないでね」という目印です。
- ここまでのメソッドは、ほぼ全部が `_call` を通して kintone に頼んでいます。

### 16-1. _call（kintone に頼む窓口係）

**役割**: `kintone.api()`（kintone 標準の通信の仕組み）を呼びます。失敗したら、処理名つきの `KintoneRecordApiError` に**変換して**投げます。

#### 塊 1: 処理名が書かれているか確認

```js
async _call(processName, method, apiPath, params) {
  if (typeof processName !== 'string' || processName.trim() === '') {
    throw new Error('KintoneRecordApi: 第 1 引数に処理名（文字列）を指定してください');
  }
```

- 処理名が「文字列でない」または「空白だけ」なら、**通信する前に**エラーにします。
- 全メソッドがここを通るので、処理名の書き忘れはどのメソッドでもここで見つかります。

#### 塊 2: 頼んでみて、成功ならそのまま返す

```js
  try {
    return await kintone.api(apiPath, method, params);
```

- `kintone.api(住所, やり方, 材料)` で、kintone に実際に頼みます。
- 成功したら、kintone の答えをそのまま返します。

#### 塊 3: 失敗したら、分かりやすいエラーに作り直す

```js
  } catch (error) {
    const { code, message } = extractKintoneErrorInfo(error);
    throw new KintoneRecordApiError({
      processName: processName,
      apiName: `${method} ${apiPath}`,
```

```js
      code: code,
      kintoneMessage: message,
      cause: error,
    });
  }
}
```

- `extractKintoneErrorInfo`（3-2）で、エラーコードとメッセージを取り出します。
- それを材料に `KintoneRecordApiError`（2 節）を作って投げます。
  - `apiName` は `GET /k/v1/records.json` のような「やり方＋住所」。
  - `cause` に元のエラーを丸ごと残します。

### 16-2. _deleteCursorQuietly（しおりを静かに片付ける）

**役割**: カーソル（しおり）を削除します。後片付け専用なので、**削除に失敗しても何も言いません**。

```js
async _deleteCursorQuietly(cursorId) {
  try {
    await kintone.api('/k/v1/records/cursor.json', 'DELETE', { id: cursorId });
  } catch (ignored) {
    // 後始末の失敗は無視する（上の説明を参照）
  }
}
```

- `DELETE` でしおりを削除します。
- `_call` ではなく `kintone.api` を**直接**呼んでいます。エラーを作り直す必要がないためです。
- `catch` の中が空 = 失敗しても何もしない。
- なぜ黙るのか:
  - ここで別のエラーを投げると、**本当の失敗理由**（7 節の元のエラー）が隠れてしまうため。
  - しおりは kintone 側でも一定時間で自動削除されるので、残っても大きな問題にならないため。

## 17. グローバルに公開（ファイルの最後）

**この節の役割**
- 箱（IIFE）の中で作ったもののうち、**利用者に使ってほしい 3 つだけ**を外に出します。

```js
globalThis.KintoneRecordApi = KintoneRecordApi;
globalThis.KintoneRecordApiError = KintoneRecordApiError;
globalThis.KINTONE_LIMITS = KINTONE_LIMITS;
```

- 📝 読み替え: `globalThis` = 「どこからでも見える共有の場所」。ここに置いたものは、後から読み込む JS からそのまま使えます。
- 公開されるのは `KintoneRecordApi`（本体）・`KintoneRecordApiError`（エラー）・`KINTONE_LIMITS`（件数制限）の 3 つ。

- このため、kintone のカスタマイズ設定では、このファイルを利用側の JS より**先に**読み込む必要があります。

## 付録: 記号の読み替え早見表

実務でつまずきやすいものだけに絞っています。

| 書き方 | 読み替え | 初登場 |
|---|---|---|
| `(function () { ... })();` | IIFE。その場で 1 回だけ実行し、中の名前を外に漏らさない | 0 節 |
| `Object.freeze(...)` | プロパティの書き換えを禁止する（`const` だけでは中身は守れない） | 1 節 |
| `({ a, b })` / `const { a, b } = x` | 分割代入。オブジェクトから a と b を取り出す | 2 節 / 12 節 |
