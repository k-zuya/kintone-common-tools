# kintone REST API 共通部品の説明メモ

対象: `src/kintoneRecordApi.js`（`KintoneRecordApi` / `KintoneRecordApiError` / `KINTONE_LIMITS`）
読者: プログラムを少し触ったことがある人（変数・関数・配列・ループ・クラス・メソッド・引数・戻り値・async/await などの基礎用語は分かるが、kintone 固有の仕組み — レコード、フィールドコード、REST API、offset、カーソル、revision など — はこれから、という段階）
関連: ソースコードを 1 行ずつ読む解説は [共通部品のコード解説メモ](./共通部品のコード解説メモ.md) にあります。

このメモの内容は、実際の kintone 環境での動作確認の結果をもとにしています（確認した範囲は第 6 章）。

使用例では、次のフィールドを持つアプリを想定しています。フィールドコードや選択肢は、自分のアプリに合わせて読み替えてください。

| フィールド | フィールドコード | 種類 |
| --- | --- | --- |
| 案件コード | `project_code` | 文字列（1 行）・値の重複禁止 |
| タイトル | `title` | 文字列（1 行） |
| 金額 | `amount` | 数値 |
| 状況 | `status` | ドロップダウン（`未着手` / `対応中` / `完了`） |

※ 各メソッドの「実務での使用例」だけは、日本語のフィールドコード（`案件コード`・`案件名`・`金額`・`期限`・`顧客コード`・`状況`）を持つアプリを想定しています。

---

## はじめに: 先に言葉の確認

このメモでよく出てくる kintone 固有の言葉です（プログラミングの基礎用語は説明を省きます）。

- **アプリ**: kintone で作る「データの入れ物」。Excel でいえば 1 枚の表のようなものです。アプリごとに番号（アプリ ID）が付いています。
- **レコード**: アプリに入っている 1 件分のデータ。表でいえば 1 行です。レコードにも番号（レコード ID）が付きます。
- **フィールドコード**: 各項目（フィールド）に付ける、プログラム用の名前です。画面に出る表示名とは別物で、プログラムからはこちらの名前で項目を指定します（例: `project_code`）。
- **REST API**: kintone のデータを、画面を使わずに外から操作するための窓口です。「この番号のレコードをください」「このレコードを登録して」と頼むと、kintone が処理して結果を返してくれます。
- **kintone.api()**: カスタマイズ JavaScript から REST API を呼ぶために、kintone があらかじめ用意してくれている関数です。この部品も中ではこれを呼んでいます。

---

## 1. この部品は何か

- `kintone.api()` を**包んだ（ラップした）クラス**です。「kintone とやり取りする窓口係」と思ってください。
  - 中で `kintone.api()` を呼んでいて、その前後に便利な処理を足しています。
- 役割は 3 つです。
  - **窓口**: 「取る・入れる・直す・消す」の頼み方を同じ形にそろえる
  - **分割**: 件数が多いとき、裏で自動的に小分けにする
    - kintone は 1 回に扱える件数が決まっているためです。取得は 500 件ずつ、登録・更新・削除は 100 件ずつ、バルク（まとめ実行）は 20 リクエストずつ
  - **エラー係**: 失敗したら「どの処理で・どの API が・なぜ」失敗したかを `KintoneRecordApiError`（この部品専用のエラークラス）で教える
- 設計の狙いは、**中身が分からなくても安全に使えること**。
  - 件数の制限や offset（何件目から取るかの目印。第 4 章で説明）の上限など、知らないと事故になる部分は部品側が面倒を見ます。
  - 件数制限の数字は `KINTONE_LIMITS` という定数にまとまっています（`WRITE_RECORDS: 100` / `GET_RECORDS: 500` / `BULK_REQUESTS: 20` / `MAX_OFFSET: 10000`）。

## 2. この部品でできること: 5つの基本操作

kintone のデータに対してできることは、大きく分けると次の 5 つです。この章では「それぞれどういう操作か」という**考え方**を説明します。メソッドの**一覧**は第 3 章の「主なメソッドの早見表」にまとめてあります。

- 使用例の `api` は、`new KintoneRecordApi(アプリID)` で作った窓口のことです（作り方は第 3 章）。
- どのメソッドも、1 番目の引数は処理名（エラー時に出る日本語の名札）です。

### ① 参照（取る）

- **何をするものか**: アプリに入っているレコードを読み出します。ふだん画面で一覧や詳細を見ている代わりに、**プログラムでデータを読む**操作です。読むだけなので、データは何も変わりません。
- **どんなときに使うか**: 「未着手の案件を数えたい」「ある案件の金額を見て計算したい」など、データを見て何かするとき。
- **対応するメソッド**:
  - `getRecord`: レコード番号を指定して **1 件**取る
  - `getRecords`: 条件に合うものを**全部**取る（500 件ずつ自動で取ってくる。取れるのは 10,500 件まで）
  - `getRecordsByCursor`: 条件に合うものを全部取る、**大量件数向け**の版（1 万件を超えそうなときはこちら）
- **使用例**:

```js
const record = await api.getRecord('詳細取得', 10);                              // 10 番のレコードを 1 件
const records = await api.getRecords('一覧取得', { query: 'amount > 1000' });     // 金額 1000 超を全部
```

**実務での使用例: `getRecord`** — 場面: 詳細画面の「見積書を作成」ボタンを押したとき、画面を開いた後に誰かが直していないか、最新の状況を読み直してから進める。

```js
const recordId = kintone.app.record.getId();
const record = await api.getRecord('見積書作成前の読み直し', recordId);
if (record.状況.value === '完了') {
  alert('この案件はすでに完了しています');
}
```

→ 嬉しいところ: 画面に表示中の古い値ではなく、kintone にある最新の値で判断できます。

**実務での使用例: `getRecords`** — 場面: 毎朝、期限を過ぎているのに完了していない案件を、期限の古い順に洗い出す。

```js
const overdue = await api.getRecords('期限切れ案件の抽出', {
  query: '期限 < TODAY() and 状況 not in ("完了") order by 期限 asc',
  fields: ['$id', '案件名', '期限'],
});
console.log(`期限切れ: ${overdue.length} 件`);
```

→ 嬉しいところ: 500 件を超えていても続きを自動で取ってくるので、件数を気にせず「全部」が手に入ります。`fields` で必要な項目だけに絞れば通信も軽くなります。

**実務での使用例: `getRecordsByCursor`** — 場面: 年度末に、数万件たまった完了案件の金額を全部足して年間売上を出す。

```js
const records = await api.getRecordsByCursor('年間売上の集計', {
  query: '状況 in ("完了")',
  fields: ['金額'],
});
const total = records.reduce((sum, record) => sum + Number(record.金額.value || 0), 0);
```

→ 嬉しいところ: offset 10,000 の壁がないので 1 万件を超えても止まりません。カーソルの作成・後片付けも部品がやってくれます。

### ② 登録（入れる）

- **何をするものか**: アプリに新しいレコードを追加します。画面の「＋（レコードを追加する）」ボタンと同じことをプログラムで行います。
- **どんなときに使うか**: 別のアプリやファイルのデータを取り込むとき、ボタン 1 つで決まった内容のレコードを作りたいとき。
- **対応するメソッド**:
  - `addRecord`: **1 件**入れる
  - `addRecords`: **複数**まとめて入れる（kintone は 1 回に 100 件までなので、100 件ずつ自動で分けて入れる）
- **使用例**:

```js
await api.addRecord('新規登録', { title: { value: 'A' } });   // title が「A」のレコードを 1 件
await api.addRecords('一括登録', [rec1, rec2]);                // 用意したレコードを複数
```

**実務での使用例: `addRecord`** — 場面: 問い合わせを受けたら、ボタン 1 つで「未着手」の案件を作り、できた案件の番号を案内する。

```js
const { id } = await api.addRecord('問い合わせから案件作成', {
  案件名: { value: '新規問い合わせ（A社）' },
  顧客コード: { value: 'C-001' },
  状況: { value: '未着手' },
});
alert(`案件 ${id} を作成しました`);
```

→ 嬉しいところ: 戻り値で新しいレコード番号（`id`）がすぐ分かるので、「作成しました」の案内やリンク作りにそのまま使えます。

**実務での使用例: `addRecords`** — 場面: 取引先から届いた CSV（ここでは読み込み済みの配列 `csvRows`）の案件を、まとめて取り込む。

```js
const records = csvRows.map((row) => ({
  案件名: { value: row.name },
  金額: { value: row.amount },
  状況: { value: '未着手' },
}));
const saved = await api.addRecords('CSV取り込み', records);
console.log(`${saved.length} 件登録しました`);
```

→ 嬉しいところ: 100 件を超えても部品が自動で 100 件ずつに分けて登録するので、件数を数えて分ける処理を書かずに済みます。

### ③ 更新（直す）

- **何をするものか**: すでにあるレコードの中身を書き換えます。**書いたフィールドだけが変わり**、書かなかったフィールドは元のまま残ります（部分更新）。「金額だけ直したいのに、他の項目まで全部書かないといけない」ということはありません。
- **どんなときに使うか**: ステータスを「完了」に変える、金額を修正する、取り込んだデータで最新の値に置き換える、など。
- **対応するメソッド**:
  - `updateRecord`: **1 件**直す
  - `updateRecords`: **複数**まとめて直す（100 件ずつ自動で分けて直す）
  - `upsert`: キー（案件コードなど）で探して、**あれば直す・なければ入れる**。取り込みのように「すでにあるか分からない」ときに便利です
  - どのレコードを直すかは、レコード番号（id）か、重複禁止フィールドの値（updateKey）で指定します（詳しくは第 3 章「updateRecord の指定方法」）。
- **使用例**:

```js
await api.updateRecord('金額の修正', { id: 10, record: { amount: { value: 5000 } } });   // 10 番の金額だけ直す
```

**実務での使用例: `updateRecord`** — 場面: 詳細画面の「完了にする」ボタンで状況を「完了」に変える。読んだ後に誰かが直していたら上書きしない。

```js
const recordId = kintone.app.record.getId();
const record = await api.getRecord('完了処理の読み込み', recordId);
await api.updateRecord('案件の完了', {
  id: recordId,
  revision: record.$revision.value,
  record: { 状況: { value: '完了' } },
});
```

→ 嬉しいところ: 書いた `状況` だけが変わり、他の項目はそのまま残ります。`revision` を付けておけば、他の人の更新を気づかずに上書きする事故を防げます（`GAIA_CO02` で止まる）。

**実務での使用例: `updateRecords`** — 場面: 期限を過ぎてもまだ「未着手」の案件を、まとめて「対応中」に切り替える。

```js
const targets = await api.getRecords('期限切れ未着手の抽出', {
  query: '期限 < TODAY() and 状況 in ("未着手")',
  fields: ['$id'],
});
await api.updateRecords('期限切れ案件の一括着手', targets.map((record) => ({
  id: record.$id.value,
  record: { 状況: { value: '対応中' } },
})));
```

→ 嬉しいところ: 何百件あっても 100 件ずつ自動で分けて更新します。戻り値で、更新した各レコードの `id` と新しい `revision` も分かります。

**実務での使用例: `upsert`** — 場面: 基幹システムから毎日出力される案件データ（読み込み済みの配列 `dailyRows`）を、案件コード（値の重複禁止）をキーに取り込む。

```js
for (const row of dailyRows) {
  const result = await api.upsert('基幹データの取り込み', {
    updateKey: { field: '案件コード', value: row.code },
    record: { 金額: { value: row.amount }, 状況: { value: row.status } },
  });
  console.log(`${row.code}: ${result.action === 'added' ? '新規登録' : '更新'}`);
}
```

→ 嬉しいところ: 「すでにあるか」を自分で調べて登録と更新を書き分ける必要がありません。新規のときは `案件コード` も自動で入ります。

### ④ 削除（消す）

- **何をするものか**: レコードを消します。
- **どんなときに使うか**: 誤って登録したデータを片付けるとき、不要になったレコードを整理するとき。
- **対応するメソッド**:
  - `deleteRecords`: レコード番号の一覧を渡して消す（1 件でも複数でも可。100 件ずつ自動で分けて消す）
- **注意**: **消したレコードは元に戻せません**。実行する前に、消す対象の番号が正しいか必ず確認してください。
- **使用例**:

```js
await api.deleteRecords('削除', [10, 11]);   // 10 番と 11 番を消す（1 件なら [10]）
```

**実務での使用例: `deleteRecords`** — 場面: 年に 1 度、期限が古い完了済みの案件を整理する。消す前に件数を見せて確認を取る。

```js
const old = await api.getRecords('削除対象の抽出', {
  query: '状況 in ("完了") and 期限 < "2025-04-01"',
  fields: ['$id'],
});
const ids = old.map((record) => record.$id.value);
if (ids.length > 0 && confirm(`${ids.length} 件を削除します。よろしいですか？`)) {
  await api.deleteRecords('古い完了案件の削除', ids);
}
```

→ 嬉しいところ: 取得した番号の配列をそのまま渡せば、100 件ずつに分けて消してくれます（消したものは戻せないので、確認は必ず挟みます）。

### ⑤ バルクリクエスト（まとめて頼む）

- **何をするものか**: 「登録して、そのあと別のレコードを更新して」のような複数の頼み事を、1 回にまとめて kintone に渡します。まとめた中のどれか 1 つでも失敗すると、全部が取り消し（ロールバック）になり、「半分だけ反映された」という中途半端な状態を防げます。
- **どんなときに使うか**: 「在庫を減らす」と「出荷記録を入れる」のように、**片方だけ成功すると困る**処理をセットで行うとき。
- **対応するメソッド**:
  - `bulk`: まとめた頼み事を実行する（kintone は 1 回に 20 件までなので、20 件ずつ自動で分ける）
  - `req`: 頼み事 1 件分の形を作るヘルパー。`bulk` に渡す材料をこれで作ります
- **注意**: 「全部取り消し」になるのは **20 件以内**のときです。20 件を超えて自動で分けられた場合、分けた単位をまたいだ取り消しはされません。
- **使用例**:

```js
const addReq = api.req('POST', '/k/v1/record.json', { app: api.appId, record: newRecord });          // 登録の頼み事
const updReq = api.req('PUT', '/k/v1/record.json', { app: api.appId, id: 10, record: changes });     // 更新の頼み事
await api.bulk('登録と更新をまとめて', [addReq, updReq]);                                             // まとめて実行
```

**実務での使用例: `bulk`** — 場面: 受注が確定したら、案件を「完了」にするのと同時に、売上アプリ（ここではアプリ ID 34）に売上を 1 件登録する。

```js
const recordId = kintone.app.record.getId();
await api.bulk('受注確定', [
  api.req('PUT', '/k/v1/record.json', { app: api.appId, id: recordId, record: { 状況: { value: '完了' } } }),
  api.req('POST', '/k/v1/record.json', {
    app: 34,   // 売上アプリのアプリ ID
    record: { 顧客コード: { value: 'C-001' }, 金額: { value: 120000 } },
  }),
]);
```

→ 嬉しいところ: 売上の登録が失敗すれば案件の「完了」も取り消されるので、「案件は完了なのに売上が無い」という食い違いが起きません。

**実務での使用例: `req`** — 場面: 一覧で選んだ複数の案件（番号の配列 `selectedIds`）を、1 回の `bulk` で「対応中」にする。

```js
const requests = selectedIds.map((id) =>
  api.req('PUT', '/k/v1/record.json', { app: api.appId, id: id, record: { 状況: { value: '対応中' } } })
);
await api.bulk('選択案件の一括着手', requests);
```

→ 嬉しいところ: `method` / `api` / `payload` というキー名を覚えて手で組み立てなくても、引数を 3 つ並べるだけで `bulk` に渡す形ができます。

## 3. 使い方

### 前提（ファイルの置き方）

アプリの設定 →「JavaScript / CSS でカスタマイズ」→「PC 用の JavaScript ファイル」に、**この順で**登録します。

1. `kintoneRecordApi.js`（この部品）
2. 自分のカスタマイズ JS

- `import` は不要です。先に読み込んだファイルが `KintoneRecordApi` などを公開するので、後のファイルからそのまま使えます。
- 順番を逆にすると「`KintoneRecordApi` が見つからない」エラーになります。

### 手順

1. **窓口を作る**: `new KintoneRecordApi(アプリID)` と書くと、そのアプリ専用の窓口ができます。
2. **メソッドを呼ぶ**: 通信を伴うので、`await api.getRecords(...)` のように `await` を付けて呼びます。
3. **第 1 引数に処理名を書く**: 何の処理かを表す日本語の**名札**です。
   - エラー表示に `[処理名]` として出るので、どこで失敗したかがすぐ分かります。
   - 書き忘れると、API を呼ぶ前にエラーになります（`KintoneRecordApi: 第 1 引数に処理名（文字列）を指定してください`）。

次のコードは「アプリの窓口を作って、状況が『未着手』のレコードを全部取ってくる」ものです。

```js
const api = new KintoneRecordApi(2);
const records = await api.getRecords('未着手一覧の取得', {
  query: 'status in ("未着手")',
});
```

- `2` はアプリ ID です（アプリを開いたときの URL `/k/2/` の数字）。
- `query` は「どんなレコードが欲しいか」という絞り込み条件です。フィールドコード（`status`）や選択肢（`未着手`）は文字列で直接書きます。
- 戻り値 `records` はレコードの配列です。1 件は `{ フィールドコード: { value: 値 } }` の形をしています（例: `records[0].status.value`）。

失敗したときは、次のような形のメッセージになります（名札・API・エラーコード・理由の順）。

```
[詳細取得] GET /k/v1/record.json でエラーが発生しました（GAIA_RE01）: 指定したレコード（id: 99999999）が見つかりません。
```

### 補足: エラーを受け取るとき

- 呼び出しは `try` / `catch` で包みます。失敗すると `catch` に飛んできます。
- `error.message` には処理名・API・エラーコード・理由が全部入っているので、**最小限は `alert(error.message)` だけでも「どの処理で・何が起きたか」が利用者に伝わります**。
- 場合分けして出し分けたいときは、`error instanceof KintoneRecordApiError` で kintone 側のエラーかどうかを見て、`error.code`（例: `GAIA_RE01`）や `error.processName` を使います。それ以外のエラーは、握りつぶさず `throw` し直すのが基本です。
- 保存イベント（`app.record.create.submit` など）では、`event.error = 'メッセージ'` と書くと、保存を止めてその文を画面に出せます。

### 主なメソッドの早見表

| メソッド | ひとことで | 使用例 |
| --- | --- | --- |
| `getRecord` | 1 件取る | `api.getRecord('詳細取得', 10)` |
| `getRecords` | 条件に合うものを全部取る（500 件ずつ自動。上限 10,500 件） | `api.getRecords('一覧取得', { query: 'amount > 1000' })` |
| `getRecordsByCursor` | 全部取る（件数無制限のカーソル版） | `api.getRecordsByCursor('全件集計', { query: '...' })` |
| `addRecord` | 1 件入れる | `api.addRecord('新規登録', { title: { value: 'A' } })` |
| `addRecords` | 複数入れる（100 件ずつ自動） | `api.addRecords('一括登録', [rec1, rec2])` |
| `updateRecord` | 1 件直す | 下の「updateRecord の指定方法」を参照 |
| `updateRecords` | 複数直す（100 件ずつ自動。id 指定と updateKey 指定の混在 OK） | `api.updateRecords('一括更新', [t1, t2])` |
| `upsert` | キーで探して、あれば直す・なければ入れる | `api.upsert('取込', { updateKey: {...}, record })` |
| `deleteRecords` | 複数消す（100 件ずつ自動） | `api.deleteRecords('削除', [10, 11])` |
| `bulk` | 複数の API をまとめて実行（20 件ずつ自動） | `api.bulk('まとめて処理', [api.req(...), api.req(...)])` |
| `req` | `bulk` に渡す 1 件分を組み立てるヘルパー | `api.req('POST', '/k/v1/record.json', { app: api.appId, record })` |

補足:

- `getRecords` の `query` に `limit` / `offset`（件数と開始位置の指定）は書かないでください。部品が自動で付け足します。
- `req` だけは処理名を取りません（API を呼ばず、形を作るだけなので）。`app`（アプリ ID）も自動では入らないので自分で書きます。
- `upsert` の戻り値には `action`（`'updated'` か `'added'`）が入り、「直した」のか「入れた」のかが分かります。
- `deleteRecords` は第 3 引数に `revisions`（版数の一覧。`ids` と同じ順の配列）を渡せます。
- 分割したときは**全体で 1 つの取引（トランザクション = 全部成功か全部取り消しかのひとまとまり）にはなりません**。途中で失敗すると、それより前の分は反映済みのまま残ります。`bulk` は 20 件以内なら「全部成功か全部失敗」です。

### updateRecord の指定方法

「どのレコードを直すか」の指定は 2 通りです。**どちらか一方だけ**を書きます（両方同時に書かない）。

- ① **id 指定**: レコード番号で指定する
- ② **updateKey 指定**: 「フィールドコード + 値」で指定する（例: 案件コードが `P-0001` のレコード）

次のコードは、①で「10 番のレコードの金額を 5000 に直す」ものです。②にするときは `id: 10,` の行を `updateKey: { field: 'project_code', value: 'P-0001' },` に置き換えます。

```js
await api.updateRecord('金額の修正', {
  id: 10,
  record: { amount: { value: 5000 } },
});
```

- updateKey に使えるのは「**値の重複を禁止する**」設定のフィールドだけです（同じ値のレコードが複数あると、どれを直すか 1 件に決まらないため）。
- `revision`（版数）を足すと、そのリビジョンのときだけ更新されます（楽観ロック → 用語ミニ辞典参照）。

### body の「枠」と「中身」

kintone API に送るデータ（**body** = 送る書類の本文）は、部品側と呼び出し側で分担しています。
書類のフォーマット（枠）は部品が用意し、記入欄（中身）はあなたが書く、というイメージです。

| 担当 | やること |
| --- | --- |
| 部品側（枠） | `app` を付ける、API が求める形に整える、件数で分割する |
| 呼び出し側（中身） | どのフィールドに何を入れるか（`record` の中身）を毎回書く |

- 中身は業務ごとに違うので、部品が決めることはできません。ここは毎回自分で書くところです。

## 4. getRecords の中身ツアー

### たとえ: 500 件ずつ運ぶ台車

倉庫（kintone）からレコードを運び出すとき、台車には 1 回 500 件までしか載りません。
そこで「何件目から積むか」を書いたメモを渡して、台車を何往復もさせます。
この「何件目から取るかの目印」が **offset** です。

### コードの流れ（4 つの塊）

`getRecords` の中では、次の 4 つを順に繰り返しています。

1. **準備**: 運んだレコードを入れる空の箱を用意し、目印（offset）を 0 件目にする
2. **お願いメモを作る**: 呼び出し側の条件（query）の後ろに「500 件、offset 件目から」を付け足す
3. **呼んで箱に入れる**: kintone に頼み、返ってきたレコードを箱に足す
   - 実際に呼ぶのは `_call` という内部用の呼び出し係です。失敗したら処理名つきのエラーに変えて知らせます。
4. **出口と次へ**: 台車が満杯（500 件）でなかったら「最後の便」なので終わり。満杯なら目印を 500 進めて、もう一往復

2 と 4 の要の部分だけ抜き出すと、こうなっています。

```js
query: `${baseQuery} limit ${limit} offset ${offset}`.trim(),   // 2. 条件の後ろに付け足す

if (response.records.length < limit) return allRecords;         // 4. 500 件未満 = もう残りなし
offset += limit;                                                // 4. 次は 500 件先から
```

### offset の壁

- kintone では offset を **10,000 までしか指定できません**。
- なので `getRecords` で取れるのは、offset 10,000 から 500 件取った **10,500 件まで**です。
- 次の offset が 10,000 を超える時点で、**API を呼ぶ前に**エラーを出して止めます。メッセージで `getRecordsByCursor` を使うよう案内します。
  - そのまま呼ぶと kintone 側の分かりにくいエラーになるので、先回りして止めています。
- **割り切り**: ちょうど 10,500 件の場合もエラーになります。
  - 最後の便が満杯（500 件）だと「まだ続きがあるかも」と判断し、次の offset（10,500）で壁に当たるためです。
  - 1 万件前後になりそうなアプリでは、最初から `getRecordsByCursor` を使ってください。

### カーソル方式 =「しおり方式」

- offset 方式は「何件目から」と**位置の数字**で指定するので、数字に上限（壁）があります。
- カーソル方式は、kintone に**しおり**を挟んでもらい、「続きをください」と頼むだけです。
  - 位置の数字を使わないので、壁がありません。
- `getRecordsByCursor` は、しおりを作る → 続きを最後まで読む → 片付ける、までを 1 つのメソッドの中で済ませます。
  - 最後まで読むと kintone が自動で片付けます。途中で失敗したときだけ部品が自分で片付けます。

## 5. 用語ミニ辞典

| 用語 | ひとことで |
| --- | --- |
| ラッパー / ラッパークラス | 既存の機能（ここでは `kintone.api()`）を包んで、使いやすくした部品。クラスの形で作ったものがラッパークラス |
| ヘルパー | 小さな下ごしらえ専門の関数。`req` は「バルク 1 件分の形を作るだけ」のヘルパー |
| インターフェース | 「この形で渡してね」という約束事（書類のフォーマットのようなもの）。JavaScript には仕組みとして無いので、代わりに JSDoc（コードに書く説明コメント）の型定義（`@typedef` など）がその役割を果たす。エディタが補完や警告で教えてくれる |
| offset | 複数取得で「何件目から取るか」を指定する数字。kintone では 10,000 が上限 |
| カーソル | kintone に挟んでもらう「しおり」。大量件数を続きから読むための仕組み |
| バルクリクエスト | 複数の API 呼び出しを 1 回にまとめて送る仕組み（`/k/v1/bulkRequest.json`）。1 回 20 件まで、まとめた中は全部成功か全部取り消し |
| 処理名 | 全メソッドの第 1 引数に書く日本語の名札。エラー表示に `[処理名]` として出る |
| updateKey | id の代わりに「重複禁止フィールドの値」で更新先を指定する方法 |
| revision（リビジョン） | レコードの版数。更新のたびに増える |
| 楽観ロック | 「自分が読んだ版のままなら更新する」という早い者勝ちの守り。誰かが先に直していたら止まる |

## 6. 動作確認済みの範囲

kintone の開発者ライセンス環境で、実際の kintone を使って次の動作を確認しています。

- **取得**: 1 件（`getRecord`）、全件・条件つき（`getRecords`）、カーソル（`getRecordsByCursor`）
- **登録**: `addRecord` / `addRecords`
- **更新**: id 指定、updateKey 指定、revision による楽観ロック、id 指定と updateKey 指定の混在
- **upsert**: 「あれば更新」「なければ登録」の両方
- **削除**: `deleteRecords`
- **バルク**: 成功、失敗時の全件巻き戻し（ロールバック）、21 件での分割（20 + 1）
- **分割（書き込み）**: 101 件の登録と削除（100 + 1 に分割）
- **分割（500 件を超える件数）**: 取得の 500 件分割、更新の 100 件分割、カーソル取得
- **エラー**: 処理名つきエラーメッセージの形式
- **offset 上限の検知**: モック（kintone の代わりに使う偽物）で 12,000 件相当を用意し、10,500 件を超えるところでカーソル版への案内エラーが出ることを確認

## 7. ハマりどころメモ

- **`like` 検索（「〜を含む」検索）で英数字コードの前方一致が効かないことがある**
  - 例: `SP` で始まる案件コードを `like` で探しても 0 件になることがあります。
  - 件数を数えたいときは、全件取得して手元（JS 側）で数えるのが確実です。
- **文字列（1 行）フィールドには `>=` や `<`（大小比較）が使えない**
  - 使うと `GAIA_IQ03` エラーになります。範囲で絞りたいときは数値・日付フィールドを使うか、全件取得して手元で絞ります。
- **revision（版数）が古い更新は `GAIA_CO02` で止まる**
  - 楽観ロックが効いている証拠です。最新の revision を取り直してからやり直します。
