## 1. flattenRecord（レコードをほぐす）

**この関数の役割**
- API で取得したレコード `{ フィールドコード: { type, value } }` から包みを外し、`{ フィールドコード: 値 }` にします。
- 例: `{ $id: { type: '__ID__', value: '1' }, title: { type: 'SINGLE_LINE_TEXT', value: 'A' } }` → `{ $id: '1', title: 'A' }`
- **数値の自動変換**: `type` が `NUMBER`（数値）・`CALC`（計算）のフィールドは、値を数値にします。空でない文字列は `Number(...)` の結果（`'12000'` → `12000`、`'3.5'` → `3.5`）、空文字列は `null`（未入力と `0` を区別するため）、すでに数値ならそのまま。サブテーブルの行の中のフィールドも同じです。それ以外の `type` の値は変換しません。
  - 例: `{ amount: { type: 'NUMBER', value: '12000' }, rate: { type: 'CALC', value: '3.5' }, qty: { type: 'NUMBER', value: '' } }` → `{ amount: 12000, rate: 3.5, qty: null }`
  - この仕様は関数の JSDoc（ソースのコメント）にも書いてあります。
- `flattenRecord` 本体のコードは「1 つずつほぐして入れ物に入れる」だけで、変換の中身は `flattenField`（2 節）が受け持ちます。数値の変換も 2 節の塊 3 で行います。

### 塊 1: フィールドを 1 つずつほぐして、新しい入れ物に入れる

```js
function flattenRecord(record) {
  const flatRecord = {};
  for (const [fieldCode, field] of Object.entries(record)) {
    flatRecord[fieldCode] = flattenField(field);
  }
  return flatRecord;
}
```

- `flatRecord` … ほぐした結果を入れる空の入れ物。
- 📝 読み替え: `for (const [fieldCode, field] of Object.entries(record))` = 「レコードの**項目名と中身を 1 組ずつ**取り出して繰り返す」。
  - `Object.entries(obj)` は、オブジェクトを `[[キー, 値], [キー, 値], ...]` という**組の配列**に変えます。
  - `[fieldCode, field]` は配列の分割代入で、組の 1 番目を `fieldCode`、2 番目を `field` に入れます。
  - 例: 1 周目は `fieldCode = '$id'`、`field = { type: '__ID__', value: '1' }`。
- 実際にほぐす作業は `flattenField`（2 節）に任せ、その結果を同じフィールドコードで入れ物に入れます。
- 元の `record` は書き換えず、**新しいオブジェクト**を作って返します。
- `$id`・`$revision` も特別扱いせず、ほかのフィールドと同じように値を取り出して、そのままのキーで残します。`type` が `NUMBER` / `CALC` ではない（`'__ID__'` / `'__REVISION__'`）ので、値は文字列のままです。
- サブテーブルの行の中身も、2 節で見るとおりこの `flattenRecord` でほぐすので、行の中の数値・計算フィールドも同じように数値になります。
- `flattenRecords`（3 節）はこの関数を 1 件ずつ呼ぶだけなので、数値の変換も自動で同じように効きます。

## 2. flattenField（フィールド 1 つをほぐす・内部）

**この関数の役割**
- フィールド 1 つ分 `{ type, value }` から値を取り出します。サブテーブルなら、行の中身までほぐします。数値・計算フィールドなら、値を数値にします。

### 塊 0: 数値に変換する type の名簿（関数の直前）

```js
/** 値を数値に変換するフィールドの type（数値・計算） */
const NUMERIC_FIELD_TYPES = new Set(['NUMBER', 'CALC']);
```

- 数値に変換する対象の `type` を、関数の外で 1 回だけ作っておきます。
- 📝 読み替え: `new Set(配列)` = 「重複のない**名簿**」を作る。後で `NUMERIC_FIELD_TYPES.has(field.type)` のように「名簿に載っているか」をすばやく調べるために使います。
- 対象の種類を増やしたいときは、この 1 行に足すだけで済みます。

### 塊 1: 想定外の形なら、手を付けずにそのまま返す

```js
function flattenField(field) {
  if (field === null || typeof field !== 'object' || !('value' in field)) {
    return field;
  }
```

- 「`null`」「オブジェクトでない」「`value` というキーを持たない」のどれかなら、ほぐしようがないので**そのまま**返します。
- `null` を最初に調べているのは、JavaScript では `typeof null` が `'object'` になってしまうためです（`typeof` だけでは `null` を弾けません）。
- `'value' in field` = 「`field` に `value` というキーがあるか」。値が空（`''` や `null`）でも、キーがあれば `true` です。

### 塊 2: サブテーブルなら、行ごとにほぐす

```js
  if (field.type === 'SUBTABLE') {
    return field.value.map((row) => ({ id: row.id, ...flattenRecord(row.value) }));
  }
```

- kintone が付けてくる `type` が `'SUBTABLE'` のときだけ、特別な処理をします。
- サブテーブルの `value` は行の配列で、1 行は `{ id: '10', value: { name: { type, value: 'りんご' }, qty: { ... } } }` の形です。
- `.map(...)` で、1 行ずつ `{ id: '10', name: 'りんご', qty: 3 }` の形に作り変えた**新しい配列**を返します。
  - 行の中身 `row.value` は、ふつうのレコードと同じ形なので `flattenRecord`（1 節）をもう一度使ってほぐしています（関数が関数を呼び合う形）。そのため、行の中の `qty`（数値）も下の塊 3 を通って `'3'` → `3` になります。
  - `{ id: row.id, ...ほぐした中身 }` で、行 ID を先頭に置いて中身を広げています（スプレッド構文）。
- 📝 読み替え: `(row) => ({ ... })` = 「オブジェクトを**返す**アロー関数」。`{` の外側の `( )` を外して `(row) => { ... }` と書くと、`{ }` が「関数の本体」と見なされてしまい、オブジェクトが返りません。
- `type` で見分けているので、`type` を持たない手作りのデータでは、サブテーブルの行はほぐされません。

### 塊 3: 数値・計算フィールドなら、値を数値にする

```js
  if (NUMERIC_FIELD_TYPES.has(field.type)) {
    return toNumberValue(field.value);
  }
```

- kintone は数値フィールド・計算フィールドの値も**文字列**（`'1200'`）で返します。そのままだと `'1200' + 1` が `'12001'`（文字のつなげ合わせ）になるなど、計算で事故が起きやすいので、ここで数値にします。
- `type` が塊 0 の名簿（`NUMBER` / `CALC`）に載っているときだけ、実際の変換を `toNumberValue`（下の 2-1）に任せます。
- `type` で見分けているので、文字列フィールドに `'12000'` と入っていても変換されません。

### 塊 4: それ以外は value をそのまま返す

```js
  return field.value;
}
```

- 文字列・日付などは、`value` の中身を返すだけです。
- ユーザー選択・添付ファイルのように値が配列やオブジェクトのフィールドも、**中身は加工せず**そのまま返します。

### 2-1. toNumberValue（値を数値にする・内部）

**役割**: 数値・計算フィールドの値を数値にします。空文字列は `null`、文字列以外はそのまま返します。数値に変換できない文字列は、値を壊さないよう元の文字列のまま返します。

```js
function toNumberValue(value) {
  if (typeof value !== 'string') {
    return value;
  }
  if (value === '') {
    return null;
  }
  const converted = Number(value);
  // 数値に変換できない文字列（計算フィールドの日付表示など）は、値を壊さないよう元の文字列のまま返す。
  return Number.isNaN(converted) ? value : converted;
}
```

- まず「文字列でなければ、そのまま返す」。すでに数値になっている値（`42` など）や `null` は手を付けません。
- 空文字列 `''`（未入力）→ `null`。`Number('')` は `0` になってしまい、「未入力」と「0 と入力した」の区別がつかなくなるためです。
- それ以外は `Number(value)` で変換します。例: `'12000'` → `12000`、`'3.5'` → `3.5`、`'-0.25'` → `-0.25`。
- 変換結果が `NaN`（数値にならない）のときは、元の文字列のまま返します。計算フィールドの表示形式が日付などの場合に `'2026-11-18'` のような文字列が返ってくることがあり、そのまま数値化すると値が壊れてしまうためです。

## 3. flattenRecords（ほぐすの配列版）

**この関数の役割**
- レコードの配列をまとめてほぐします。

```js
function flattenRecords(records) {
  return records.map(flattenRecord);
}
```

- `records.map(flattenRecord)` = 配列の 1 件 1 件に `flattenRecord`（1 節）をかけて、結果の配列を返します。
- `.map((record) => flattenRecord(record))` と同じ意味を、関数の名前を直接渡して短く書いています。
- 使い方の例（ソースのコメントより）: `const records = KintoneRecordUtils.flattenRecords(response.records);`

## 4. wrapRecord（レコードを包む）

**この関数の役割**
- ほぐした形 `{ フィールドコード: 値 }` を、登録・更新用の `{ フィールドコード: { value: 値 } }` に包みます。
- すでに `{ value: ... }` の形のものは二重に包みません。`null` は `{ value: null }` になります（フィールドを空にする用途）。
- 第 2 引数 `options.subtables` に挙げたフィールドは、サブテーブルとして行の中身まで包み直します。

### 塊 1: サブテーブルとして扱うフィールドコードの一覧を作る

```js
function wrapRecord(values, options) {
  const subtableCodes = new Set((options && options.subtables) || []);
  const wrappedRecord = {};
```

- `(options && options.subtables) || []` は 2 段構えです。
  - `options && options.subtables` … `options` が渡されていれば `options.subtables` を読む。渡されていなければ（`undefined`）右側は読まない（ガード）。
  - `... || []` … 結果が無ければ空の配列を使う（既定値）。
  - だから `wrapRecord(values)` と第 2 引数を省略しても動きます。
- `new Set(配列)` は 2 節の塊 0 で見た「名簿」です。後で `subtableCodes.has('items')` のように「名簿に載っているか」を調べるために使います。
- `wrappedRecord` … 包んだ結果を入れる空の入れ物。

### 塊 2: フィールドを 1 つずつ包む

```js
  for (const [fieldCode, value] of Object.entries(values)) {
    if (subtableCodes.has(fieldCode) && Array.isArray(value)) {
      wrappedRecord[fieldCode] = { value: value.map(wrapSubtableRow) };
    } else {
      wrappedRecord[fieldCode] = isWrapped(value) ? value : { value: value };
    }
  }
  return wrappedRecord;
}
```

- 1 節と同じく `Object.entries` で項目名と値を 1 組ずつ取り出します。
- **サブテーブルの場合**（名簿に載っていて、しかも値が配列）:
  - 各行を `wrapSubtableRow`（5 節）で包み、全体を `{ value: [...] }` で包みます。
  - `Array.isArray(value)` = 「値が配列か」。名簿に載っていても、値が配列でなければ（すでに `{ value: [...] }` の形など）下のふつうの扱いになります。
- **それ以外の場合**:
  - `isWrapped(value)`（6 節）で「すでに包まれているか」を調べ、包まれていればそのまま、そうでなければ `{ value: 値 }` で包みます（三項演算子 `条件 ? A : B`）。
  - `null` は「包まれていない」と判定されるので `{ value: null }` になります。
- 名簿に載せていないサブテーブルは、行の配列がそのまま `{ value: [...] }` で包まれるだけで、行の中身は包まれません。サブテーブルを渡すときは `subtables` の指定が必要です。

## 5. wrapSubtableRow（サブテーブルの行を包む・内部）

**この関数の役割**
- ほぐした行 `{ id, フィールドコード: 値, ... }` を、kintone のサブテーブルの行の形 `{ id, value: { フィールドコード: { value: 値 } } }` に包みます。

### 塊 1: id とそれ以外に分ける

```js
function wrapSubtableRow(row) {
  const { id, ...cells } = row;
  const wrappedRow = { value: wrapRecord(cells) };
```

- 📝 読み替え: `const { id, ...cells } = row;` = 「`row` から `id` だけを取り出し、**残り全部**を `cells` という新しいオブジェクトにまとめる」（残余構文）。
  - 例: `row` が `{ id: '10', name: 'りんご', qty: 3 }` なら、`id = '10'`、`cells = { name: 'りんご', qty: 3 }`。
  - 元の `row` は書き換わりません。
- 行の中身 `cells` は、ふつうのレコードと同じルールで包めばよいので `wrapRecord`（4 節）をもう一度使っています。
  - 例: `{ name: 'りんご', qty: 3 }` → `{ name: { value: 'りんご' }, qty: { value: 3 } }`
  - ここでは `options` を渡していないので、行の中をさらにサブテーブルとして包むことはしません（kintone のサブテーブルは入れ子にできないため、それで足ります）。

### 塊 2: id があれば付け、なければ付けない

```js
  return id === undefined || id === null ? wrappedRow : { id, ...wrappedRow };
}
```

- `id` が「無い」（`undefined` か `null`）なら、`{ value: {...} }` だけを返します。
- `id` があれば、`{ id, ...wrappedRow }` で先頭に `id` を付けた新しいオブジェクトを返します。
  - 📝 読み替え: `{ id }` = `{ id: id }` の省略形。変数名とキー名が同じときはこう書けます。
- `id` の無い行は、kintone では**新しい行**として追加されます。

## 6. isWrapped（包まれているか調べる・内部）

**この関数の役割**
- 値がすでに `{ value: ... }` の形になっているかを `true` / `false` で返します。`wrapRecord` が二重に包まないための判定です。

```js
function isWrapped(value) {
  return value !== null && typeof value === 'object' && !Array.isArray(value) && 'value' in value;
}
```

- 4 つの条件が**全部**そろったときだけ `true` です。
  1. `null` でない（`typeof null` が `'object'` になるため先に弾く。2 節と同じ理由）
  2. オブジェクトである
  3. 配列でない
  4. `value` というキーを持っている
- 3 の「配列は除く」が大事な点です。ユーザー選択や添付ファイルの値は**配列そのもの**なので、これは「包まれていない値」として扱い、`{ value: [...] }` に包む必要があります。
- `&&` は左から順に調べ、どこかで `false` になればそこで止まります。`null` のときに `'value' in null` まで進んでエラーになることはありません。

## 7. buildRecord（必要なフィールドだけ抜き出して、登録・更新用に組み立てる）

**この関数の役割**
- レコード（取得結果や画面イベントの `event.record`）から、`fields` に挙げたフィールドだけを抜き出し、登録・更新用の `{ フィールドコード: { value: 値 } }` の形にして返します。
- フィールドが多い登録・更新で、`{ value: ... }` を 1 つずつ書く手間を減らすためのものです。
- 例: `buildRecord(event.record, ['title', 'amount'])` → `{ title: { value: 'A' }, amount: { value: 12000 } }`
- 第 3 引数 `options.subtables` は `wrapRecord`（4 節）と同じ意味で、そのまま渡されます。

### 塊 1: いったんほぐす

```js
function buildRecord(record, fields, options) {
  const flat = flattenRecord(record);
  const picked = {};
```

- まず `flattenRecord`（1 節）で、レコード全体を `{ フィールドコード: 値 }` の形にほぐします。
  - そのため、数値・計算フィールドはここで数値になり（2 節の塊 3）、サブテーブルは行ごとにほぐされます（2 節の塊 2）。
- `picked` … 抜き出したフィールドを入れる空の入れ物。

### 塊 2: 指定されたフィールドだけを拾う

```js
  for (const fieldCode of fields) {
    if (fieldCode in flat) {
      picked[fieldCode] = flat[fieldCode];
    }
  }
```

- `for (const fieldCode of fields)` … `fields` の配列から、フィールドコードを 1 つずつ取り出して繰り返します。1 節の `Object.entries` と違い、ここでは配列をそのまま回しています。
- `fieldCode in flat` = 「ほぐしたレコードに、そのフィールドコードのキーがあるか」（2 節の塊 1 で見た `in` と同じ）。
  - 元のレコードに無いフィールドコードは、ここで飛ばされて結果に含まれません。エラーにもなりません。
  - 値が空（`''` や `null`）でも、キーがあれば拾います。
- 拾う順番は `fields` に書いた順です。

### 塊 3: 包み直して返す

```js
  return wrapRecord(picked, options);
}
```

- 拾ったフィールドを `wrapRecord`（4 節）で登録・更新用の形に包み直して返します。`options` もそのまま渡すので、`subtables` に挙げたサブテーブルは行の中身まで包み直されます（行の `id` も残ります。5 節）。
- 「ほぐす → 拾う → 包む」の 3 段で、既存の関数を組み合わせているだけです。新しい変換のルールは増えていません。
- `$id`・`$revision` も `flattenRecord` で残るので、`fields` に入れると拾われてしまいます。登録・更新の `record` には含められないため、`fields` には入れないでください（ソースのコメントより）。

## 8. userCodes / userNames / toUserArray（ユーザー選択などの値を取り出す）

**この節の役割**
- ユーザー選択・組織選択・グループ選択フィールドの値から、`code` だけ・`name` だけの配列を取り出します。
- これらのフィールドの値は `[{ code, name }, ...]` の**配列**ですが、作成者・更新者は `{ code, name }` の**単体**です。どちらも受け付け、戻り値は常に配列にします。`null`・`undefined`・空配列なら空配列です。
- 例: `userCodes([{ code: 'sato', name: '佐藤' }, { code: 'suzuki', name: '鈴木' }])` → `['sato', 'suzuki']`、`userNames({ code: 'sato', name: '佐藤' })` → `['佐藤']`

### 8-1. userCodes / userNames（公開）

```js
function userCodes(users) {
  return toUserArray(users).map((user) => user.code);
}
```

```js
function userNames(users) {
  return toUserArray(users).map((user) => user.name);
}
```

- どちらも 1 行で、違いは取り出す項目（`code` か `name` か）だけです。
- まず `toUserArray`（下の 8-2）で「必ず配列」の形にそろえ、それから `.map(...)` で 1 人ずつ `code`（または `name`）を取り出した**新しい配列**を返します。
  - 例: `[{ code: 'sato', name: '佐藤' }, { code: 'suzuki', name: '鈴木' }]` → `userCodes` なら `['sato', 'suzuki']`。
- 形をそろえる仕事を `toUserArray` に任せているので、2 つの関数は「取り出す」ことだけに集中できます。
- 空配列に `.map(...)` をかけると空配列が返るので、未選択（`[]`）の場合も特別扱いは要りません。

### 8-2. toUserArray（配列にそろえる・内部）

```js
function toUserArray(users) {
  if (users === null || users === undefined) {
    return [];
  }
  return Array.isArray(users) ? users : [users];
}
```

- 受け取った値を、3 通りに分けて**必ず配列**にします。
  1. `null` か `undefined`（値が無い）→ 空配列 `[]`
  2. 配列 → そのまま
  3. それ以外（作成者・更新者のような単体の `{ code, name }`）→ `[users]` で**1 件だけの配列**に包む
- `Array.isArray(users)` は 4 節でも出てきた「値が配列か」の判定です。
- 📝 読み替え: `Array.isArray(x) ? x : [x]` = 「配列ならそのまま、そうでなければ 1 件の配列にする」。**呼び出し側が「配列か単体か」を気にしなくて済む**ようにする、よくある書き方です。
- 最初に `null` / `undefined` を弾いているのは、弾かないと `[null]` という「中身が `null` の 1 件の配列」になり、続く `.map((user) => user.code)` で `null.code` を読もうとしてエラーになるからです。

## 9. 日付の内部補助（parseDateText / toDateText / utcDateToText）

**この節の役割**
- 日付ヘルパー（10〜15 節）が共通して使う下ごしらえ係 3 つです。
- このファイルの日付は、受け渡しをすべて `YYYY-MM-DD` の**文字列**で行います。計算は `Date.UTC` で行い、実行環境のタイムゾーンや夏時間で日付がずれないようにしています（ソースの区切りコメントより）。

### 9-1. parseDateText（文字列を年・月・日に分解する）

**役割**: `'2026-11-18'` を `{ year: 2026, month: 11, day: 18 }` に分けます。形式が違う・存在しない日付なら `Error` を投げます。

#### 塊 1: 形式を確かめる

```js
function parseDateText(dateText) {
  const match = /^(\d{4})-(\d{2})-(\d{2})$/.exec(String(dateText));
  if (!match) {
    throw new Error(`KintoneRecordUtils: 日付は YYYY-MM-DD 形式で指定してください（${dateText}）`);
  }
```

- 📝 読み替え: `/^(\d{4})-(\d{2})-(\d{2})$/` = **正規表現**（文字の並びのパターン）。
  - `^` と `$` … 「先頭から最後まで全体が」この形であること。前後に余計な文字があると不一致になります。
  - `\d{4}` … 数字 4 個。`\d{2}` … 数字 2 個。
  - `( )` … その部分を後で取り出せるように**印を付ける**。
- `.exec(文字列)` は、一致すれば結果の配列、一致しなければ `null` を返します。
- `String(dateText)` で、念のため文字列に変えてから調べます（`null` を渡しても `'null'` という文字列になり、不一致としてエラーになります）。
- 一致しなければ、受け取った値をメッセージに入れてエラーにします。
  - 例: `'2026/11/18'`（区切りが違う）、`'2026-11-18T00:00:00Z'`（日時の形）、`'2026-1-5'`（桁が足りない）はどれもエラー。

#### 塊 2: 印を付けた部分を数値にする

```js
  const year = Number(match[1]);
  const month = Number(match[2]);
  const day = Number(match[3]);
```

- `match[0]` は一致した全体、`match[1]`〜`match[3]` が `( )` で印を付けた部分です（年・月・日の順）。
- 取り出した直後は文字列（`'11'` など）なので、`Number(...)` で数値にします。

#### 塊 3: 存在しない日付を見つける

```js
  // 2026-02-30 のような存在しない日付は、Date に通すと別の日に繰り上がるので検知できる
  const date = new Date(Date.UTC(year, month - 1, day));
  if (date.getUTCMonth() !== month - 1 || date.getUTCDate() !== day) {
    throw new Error(`KintoneRecordUtils: 存在しない日付です（${dateText}）`);
  }
  return { year, month, day };
}
```

- 形式は正しくても `'2026-02-30'` のような日付はありえません。それを見つける仕掛けです。
- 📝 読み替え: `Date.UTC(年, 月, 日)` の**月は 0 始まり**（1 月 = 0、12 月 = 11）。だから `month - 1` を渡しています。
- `Date` は、はみ出した日付を**自動で繰り上げ**ます。2 月 30 日を渡すと 3 月 2 日（2026 年は平年なので）になります。
- 作った日付の月・日を読み戻し（`getUTCMonth()` / `getUTCDate()`）、渡した月・日と**違っていたら**「繰り上がった ＝ 存在しない日付」と判断してエラーにします。
- `getUTC...` を使うのは、`Date.UTC` で作った日付を同じ UTC の基準で読むためです（タイムゾーンの影響を受けません）。
- 問題なければ `{ year, month, day }`（`{ year: year, ... }` の省略形）を返します。月は 1〜12 のままです。

### 9-2. toDateText（年・月・日から文字列を作る）

**役割**: `(2026, 3, 5)` → `'2026-03-05'` のように、桁をそろえた文字列を作ります。

```js
function toDateText(year, month, day) {
  const yyyy = String(year).padStart(4, '0');
  const mm = String(month).padStart(2, '0');
  const dd = String(day).padStart(2, '0');
  return `${yyyy}-${mm}-${dd}`;
}
```

- 📝 読み替え: `文字列.padStart(桁数, '0')` = 「足りない桁を**左側から** `'0'` で埋める」。
  - 例: `'3'.padStart(2, '0')` → `'03'`、`'11'.padStart(2, '0')` → `'11'`（足りていれば何もしない）。
- 数値のままでは `padStart` が使えないので、先に `String(...)` で文字列にしています。
- 最後にテンプレート文字列で `-` を挟んでつなげます。

### 9-3. utcDateToText（UTC の Date から文字列を作る）

**役割**: `Date.UTC` で作った `Date` を `'YYYY-MM-DD'` にします。`addDays` と `monthEnd` の最後の仕上げに使います。

```js
function utcDateToText(utcDate) {
  return toDateText(utcDate.getUTCFullYear(), utcDate.getUTCMonth() + 1, utcDate.getUTCDate());
}
```

- `Date` から UTC の基準で年・月・日を読み、`toDateText`（9-2）に渡すだけです。
- `getUTCMonth()` は 0 始まりなので、`+ 1` して 1〜12 に戻しています（9-1 の `month - 1` の逆）。

## 10. today（今日の日付）

**この関数の役割**
- 今日の日付を `'YYYY-MM-DD'` で返します。例: `'2026-11-18'`

```js
function today() {
  const now = new Date();
  return toDateText(now.getFullYear(), now.getMonth() + 1, now.getDate());
}
```

- `new Date()` … 今この瞬間の日時。
- ここだけは `getUTC...` ではなく、`getFullYear()` / `getMonth()` / `getDate()`（**現地時刻**の読み方）を使っています。
  - 利用者にとっての「今日」は、そのブラウザの現地時刻での日付だからです。UTC で読むと、日本時間の午前 0〜9 時には前日の日付になってしまいます。
  - その代わり、パソコンの時計や時刻設定がずれていると、結果もずれます。
- `getMonth()` も 0 始まりなので `+ 1` しています。

## 11. addDays（何日後・何日前）

**この関数の役割**
- 日付に `days` 日を足した日付を返します。負の数なら何日前になります。月またぎ・年またぎも扱えます。
- 例: `addDays('2026-11-28', 5)` → `'2026-12-03'`

```js
function addDays(dateText, days) {
  const { year, month, day } = parseDateText(dateText);
  return utcDateToText(new Date(Date.UTC(year, month - 1, day + days)));
}
```

- まず `parseDateText`（9-1）で年・月・日に分けます（形式違いならここでエラー）。
- `Date.UTC(year, month - 1, day + days)` で、**日の数字に days をそのまま足して**しまいます。
  - 例: 11 月 28 日 + 5 → 「11 月 33 日」を渡すことになりますが、9-1 で見た**自動繰り上げ**のおかげで 12 月 3 日になります。
  - 負の場合も同じで、3 月 1 日 − 1 → 「3 月 0 日」→ 2 月の末日（2 月 28 日）になります。
- 9-1 では「繰り上げ」を**誤りの検知**に使い、ここでは**計算の道具**として使っているわけです。
- 最後に `utcDateToText`（9-3）で文字列に戻します。
- UTC で計算しているので、夏時間のある地域でも「1 日が 23 時間」のような影響を受けず、日付がずれません。
- `days` は**数値**で渡してください。文字列の `'5'` を渡すと、`day + days` が足し算ではなく文字のつなげ合わせ（28 と `'5'` → `'285'`）になり、正しい結果になりません。

## 12. monthEnd（月末日）

**この関数の役割**
- 渡した日付が属する月の末日を返します。うるう年も考慮されます。
- 例: `monthEnd('2028-02-10')` → `'2028-02-29'`

```js
function monthEnd(dateText) {
  const { year, month } = parseDateText(dateText);
  // 「翌月の 0 日」は「その月の末日」になる
  return utcDateToText(new Date(Date.UTC(year, month, 0)));
}
```

- `parseDateText` の結果から、年と月だけを取り出します（日は使いません）。
- ポイントは `Date.UTC(year, month, 0)` です。
  - `month` は 1 始まり（2 月なら 2）ですが、`Date.UTC` には 0 始まりで渡す決まりなので、`month` をそのまま渡すと「**翌月**」（3 月）の意味になります。
  - そこに日として `0` を渡すと、「翌月の 1 日の前日」＝**その月の末日**に繰り下がります。
  - 例: 2028 年 2 月 → `Date.UTC(2028, 2, 0)` → 3 月 0 日 → 2 月 29 日。
  - 12 月も `Date.UTC(year, 12, 0)` → 翌年 1 月 0 日 → 12 月 31 日と、正しく求まります。
- 月ごとの日数表やうるう年の計算を自分で書かず、`Date` の繰り上げ・繰り下げに任せているので、短く確実です。

## 13. formatDate（表示用の書式に変える）

**この関数の役割**
- 書式 `pattern` の中の `YYYY`・`MM`・`DD` を、年（4 桁）・月（2 桁）・日（2 桁）に置き換えた文字列を返します。
- 例: `formatDate('2026-11-18', 'YYYY/MM/DD')` → `'2026/11/18'`、`'YYYY年MM月DD日'` → `'2026年11月18日'`

```js
function formatDate(dateText, pattern) {
  const { year, month, day } = parseDateText(dateText);
  const [yyyy, mm, dd] = toDateText(year, month, day).split('-');
  return pattern.replace(/YYYY/g, yyyy).replace(/MM/g, mm).replace(/DD/g, dd);
}
```

- まず `parseDateText`（9-1）で、形式と日付の正しさを確かめます（返すのは書式の文字列ですが、入力のチェックは他と同じです）。
- `toDateText(...).split('-')` で、桁をそろえた `'2026-11-18'` を `-` で区切り、`['2026', '11', '18']` にします。それを配列の分割代入で `yyyy` / `mm` / `dd` に入れます。
  - 桁そろえを `toDateText`（9-2）に任せて、同じ処理を二度書かないようにしています。
- `.replace(/YYYY/g, yyyy)` … 書式の中の `YYYY` を**全部**（`g` = 全部の該当箇所）年に置き換えます。続けて `MM`、`DD` も同様に置き換えます。
- 置き換わるのは大文字の `YYYY` / `MM` / `DD` だけです。小文字の `yyyy` などは置き換わりません。また、書式の中にこれらの文字が別の意味で含まれていても置き換わります。

## 14. diffDays（2 つの日付の差）

**この関数の役割**
- 2 つの日付の差を、日数（`toDateText` − `fromDateText`）の整数で返します。`toDateText` の方が前なら負の数です。
- 例: `diffDays('2026-11-28', '2026-12-03')` → `5`、`diffDays('2026-12-03', '2026-11-28')` → `-5`

### 塊 0: 1 日のミリ秒数（関数の直前）

```js
/** 1 日のミリ秒数 */
const MS_PER_DAY = 24 * 60 * 60 * 1000;
```

- 24 時間 × 60 分 × 60 秒 × 1000 ミリ秒 ＝ 86,400,000。`Date` の時刻は**ミリ秒**単位の数値なので、日数に直すときにこれで割ります。
- `86400000` と書くより、掛け算のまま書いた方が「何の数か」が読み取れます。

### 塊 1: 両方の日付を、UTC のミリ秒の数値にする

```js
function diffDays(fromDateText, toDateText) {
  const from = parseDateText(fromDateText);
  const to = parseDateText(toDateText);
  const fromTime = Date.UTC(from.year, from.month - 1, from.day);
  const toTime = Date.UTC(to.year, to.month - 1, to.day);
```

- まず `parseDateText`（9-1）で、両方の日付を年・月・日に分けます（形式違い・存在しない日付ならここでエラー）。
- `Date.UTC(...)` は、`new Date(...)` で包まずに使うと、「1970-01-01 0 時（UTC）からのミリ秒数」という**ただの数値**を返します。
  - 例: `Date.UTC(2026, 10, 28)` → 2026-11-28 0 時（UTC）のミリ秒数。月が 0 始まりなので `month - 1` を渡すのは 9-1 と同じです。
- 📝 読み替え: 引数名 `toDateText` は、9-2 の関数 `toDateText` と**同じ名前**です。関数の中では引数の方が優先され、関数 `toDateText` は見えなくなります（「名前を隠す」と言います）。`diffDays` の中では関数 `toDateText` を使っていないので、動きに問題はありません。

### 塊 2: ミリ秒の差を 1 日の長さで割る

```js
  // UTC には夏時間が無く 1 日が必ず MS_PER_DAY なので、割り切れて整数になる
  return (toTime - fromTime) / MS_PER_DAY;
}
```

- 2 つのミリ秒数の差を、1 日のミリ秒数（塊 0）で割れば日数になります。後ろから前を引いているので、`toDateText` の方が前なら負の数になります。
- UTC で計算しているのがポイントです。
  - 現地時刻（`new Date(年, 月, 日)`）で計算すると、夏時間の切り替え日をまたぐときに 1 日が 23 時間や 25 時間になり、割り算の結果が `4.958...` のような半端な数になってしまいます。
  - UTC には夏時間が無いので、どの 2 日の差も必ず 86,400,000 の倍数になり、割り切れて**整数**になります。だから `Math.round` などで丸める必要がありません。
- 月またぎ・年またぎ・うるう年は、`Date.UTC` がミリ秒数を正しく数えてくれるので、自分で月の日数を数える必要はありません（例: `diffDays('2028-02-28', '2028-03-01')` → `2`）。

## 15. daysUntil（今日から何日）

**この関数の役割**
- 今日から `dateText` までの日数を返します。締切まであと何日かの表示に使います。今日なら `0`、過ぎていれば負の数です。
- 例: 今日が 2026-11-18 のとき `daysUntil('2026-11-25')` → `7`

```js
function daysUntil(dateText) {
  return diffDays(today(), dateText);
}
```

- `today()`（10 節）で今日の日付を作り、`diffDays`（14 節）に「今日 → `dateText`」の順で渡すだけです。
- 「今日」は `today()` と同じく**ブラウザの現地時刻**での日付です。日数の計算そのものは `diffDays` が UTC で行うので、タイムゾーンや夏時間でずれません。

## 16. toHalfWidthNumber（数値まわりの全角を半角に直す）

**この関数の役割**
- 日本語入力のまま打たれた「１２，０００」のような文字列の、数値まわりの全角文字を半角に直します。
- 変換するのは数字（０-９）、小数点（．→ .）、カンマ（，→ ,）、マイナス・ハイフン類（－・ー・―・‐・–・—・− → -）だけです。それ以外の文字は触りません。
- 例: `toHalfWidthNumber('１２，０００')` → `'12,000'`、`toHalfWidthNumber('０９０ー１２３４')` → `'090-1234'`

```js
function toHalfWidthNumber(text) {
  if (typeof text === 'number') {
    return String(text);
  }
  if (typeof text !== 'string') {
    return text;
  }
  return text
    .replace(/[０-９]/g, (ch) => String.fromCharCode(ch.charCodeAt(0) - 0xfee0))
    .replace(/．/g, '.')
    .replace(/，/g, ',')
    .replace(/[－ー―‐–—−]/g, '-');
}
```

- 最初の 2 つの `if` は入り口の振り分けです。数値が来たら文字列にして返し、文字列でも数値でもないもの（`null` など）はそのまま返します。
- 📝 読み替え: `[０-９]` = 「０から９までのどれか 1 文字」という正規表現のパターンで、`g` は「全部置き換える」の指定です。
- 全角数字は、文字コードを `0xfee0` ずらすと対応する半角数字になります。`String.fromCharCode(...)` は文字コードから文字を作る命令です。
- 小数点・カンマ・ハイフン類は、対象が数種類だけなので、そのまま置き換えを並べています。

## 17. setFieldErrors（画面の入力チェックでエラーを付ける）

**この関数の役割**
- 画面イベント（`app.record.create.submit` など、保存ボタンを押したときのイベント）で、フィールドごとにエラーメッセージを付けます。
- `errors` は `{ フィールドコード: メッセージ }` の対応表です。`event.record[フィールドコード].error` にメッセージを入れると、kintone はそのフィールドの下にメッセージを出し、保存を止めます。
- `topMessage` を渡すと `event.error` にも入れます（画面の上部に出る全体向けのメッセージ）。エラーを 1 件も付けられなかったときは入れません。
- `event.record` に無いフィールドコードは、`console.warn` で知らせて飛ばします。戻り値は、エラーを付けたフィールドの件数です。
- 例: `setFieldErrors(event, { title: 'タイトルを入力してください' }, '入力内容を確認してください')` → `1`
- このファイルの中で、**引数の中身を書き換える**のはこの関数だけです（ほかの関数は新しい値を作って返します）。kintone の画面イベントは「受け取った `event` を書き換えて返す」決まりなので、それに合わせています。

### 塊 1: 対応表を 1 組ずつ見て、フィールドにエラーを付ける

```js
function setFieldErrors(event, errors, topMessage) {
  let count = 0;
  for (const [fieldCode, message] of Object.entries(errors)) {
    const field = event.record[fieldCode];
    if (!field) {
      console.warn(`setFieldErrors: フィールド「${fieldCode}」が event.record にありません`);
      continue;
    }
    field.error = message;
    count += 1;
  }
```

- `count` … エラーを付けた件数を数える変数。後から増やすので `const` ではなく `let` で作っています。
- `Object.entries(errors)` で、対応表のフィールドコードとメッセージを 1 組ずつ取り出します（1 節と同じ書き方）。
- `event.record[fieldCode]` で、画面のレコードからそのフィールドを取り出します。画面イベントの `event.record` は包まれた形 `{ フィールドコード: { type, value } }` なので、`field` は `{ type, value }` のオブジェクトです。
- `if (!field)` … フィールドが見つからない（`undefined`）とき。フィールドコードの書き間違いなどで起きます。
  - `console.warn(...)` で、ブラウザの開発者ツールのコンソールに警告を出します。
  - 📝 読み替え: `continue` = 「この周の残りを飛ばして、**次の周**に進む」。ループ全体は止めません（止めるのは `break`）。1 件の書き間違いで、ほかのフィールドのエラーまで付かなくなる事故を防いでいます。
- 見つかったら `field.error = message` でメッセージを入れ、`count` を 1 増やします。
  - `field` は `event.record` の中のオブジェクトそのものを指しているので、ここで書き換えると `event.record[fieldCode].error` が書き換わります（コピーではありません）。

### 塊 2: 上部のメッセージを付けて、件数を返す

```js
  if (count > 0 && topMessage) {
    event.error = topMessage;
  }
  return count;
}
```

- 2 つの条件がそろったときだけ、`event.error` に `topMessage` を入れます。
  1. `count > 0` … フィールドのエラーを 1 件以上付けた。全部が見つからなかったときに、上部のメッセージだけが出て「どこが悪いのか分からない」状態になるのを防ぎます。
  2. `topMessage` … 第 3 引数が渡されている（省略すると `undefined` で、条件は成り立ちません）。空文字列 `''` も成り立ちません。
- 最後に付けた件数を返します。`errors` が空（`{}`）ならループは 1 周もせず、`0` が返ります。
- 画面にエラーを反映させるには、呼び出し側のイベント処理で**最後に `event` を返す**必要があります（`return event;`）。この関数は `event` を書き換えるだけで、返す役は呼び出し側です。

## 18. グローバルに公開（ファイルの最後）

**この節の役割**
- 箱（IIFE）の中で作った関数のうち、**利用者に使ってほしい 14 個だけ**を 1 つのオブジェクトにまとめて外に出します。

```js
globalThis.KintoneRecordUtils = Object.freeze({
  flattenRecord,
  flattenRecords,
  wrapRecord,
  buildRecord,
  userCodes,
  userNames,
  today,
  addDays,
  monthEnd,
  formatDate,
  diffDays,
  daysUntil,
  toHalfWidthNumber,
  setFieldErrors,
});
```

- 📝 読み替え: `globalThis` = 「どこからでも見える共有の場所」。ここに置いたものは、後から読み込む JS からそのまま `KintoneRecordUtils.wrapRecord(...)` のように使えます。
- `{ flattenRecord, flattenRecords, ... }` は `{ flattenRecord: flattenRecord, ... }` の省略形（5 節で見た書き方）です。
- 📝 読み替え: `Object.freeze(...)` = 「凍らせる」。後から `KintoneRecordUtils.addDays = ...` のように中身を書き換えられないようにします。ほかの JS がうっかり上書きする事故を防ぎます。
- 公開されないもの: `NUMERIC_FIELD_TYPES`・`flattenField`・`toNumberValue`・`wrapSubtableRow`・`isWrapped`・`toUserArray`・`parseDateText`・`toDateText`・`utcDateToText`・`MS_PER_DAY`（内部の道具なので）。
- このため、kintone のカスタマイズ設定では、このファイルを利用側の JS より**先に**読み込む必要があります。

## 付録: 記号の読み替え早見表

実務でつまずきやすいものだけに絞っています。

| 書き方 | 読み替え | 初登場 |
